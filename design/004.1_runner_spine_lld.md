> **How to use this document (implementing agent, read first).**
> This is a build spec, not a discussion. Every schema, signature, resource, and algorithm here is normative. Implement in the milestone order of §13; each milestone's acceptance criteria are `make` targets that must pass. Where behavior is not specified, do the simplest thing consistent with the invariants in §14 — do not add capabilities, hooks, options, or "improvements". If a genuine contradiction or gap blocks you, stop and surface it.
>
> The entire acceptance loop runs locally without AWS: data-path effects run on **local Spark + a Hadoop (filesystem) Iceberg catalog**, the run ledger on **pyiceberg SqlCatalog**, EventBridge under **moto**, and the router against a **record-of-functions SFN double**. Terraform is validated with `terraform validate` + `plan`; a real account is touched only at deploy time (M6).
>
> **Boundary discipline.** 004 §5–§6 are the architecture; this document hardens them to field level. Stage *behavior* that 004 defers to 005–008 stays deferred: where this LLD must ship *something* for the identity pipeline to run (delivery reading, pre_check rules, violation subtraction, fold ordering key), the mechanism is built here and explicitly marked **provisional**, with the owning doc named (§15.2). A provisional mechanism must be replaceable without touching the spine's contracts — that is the test of whether it was scoped correctly, and it is why no provisional knob appears in `PipelineSpecModel` [C-4].

## 1. Purpose, Scope, Non-Goals

Discharges every obligation 004 assigns to "004.1": BatchContext field types (§6.3), `RunConfig` tuning surface (§6.4), the one-commit invariant's mechanics (I-4, §7.6), run-ledger schema + retention + alarm thresholds (§6.5, §11), CI wall-time mitigations (§12.1), contract-fixture conventions (§12.5), the single-flight test substrate decision (I-13), and Glue↔EMR entrypoint parity kept structural (I-14).

**In scope (build all of this):**

1. The **`spine` package** — context, eight stage functions, sequence driver, effects records + implementations, pure planners, dataframe-pure `frames/` layer.
2. **Orchestration** — router Lambda, Step Functions state machine template, Glue entrypoint; single-flight via execution naming (004 D-10).
3. The **run ledger** — Iceberg table, bootstrap, per-transition best-effort appends, Athena console queries, maintenance cadence.
4. **Repo-level promotions** — purity linter to `tools/` with per-package config (004 D-8); shared event-contract fixtures under `contracts/` (004 D-13).
5. **Terraform** for the spine platform (router, bus rule, DLQ, Glue db, alarms) and a per-pipeline module (state machine + Glue job + **the job's IAM role** — per-pipeline by design, I-21), instantiated once for the identity exemplar.
6. The **identity exemplar pipeline** — fixture delivery → raw → facts → state → `batch-completed`, entirely local; the executable form of 003's phase gate.

**Out of scope (do not build):**

- Raw/quarantine schemas, verbatim/decompression semantics, `format_hints` interpretation, row attribution → **005**. This LLD's delivery reader and pre_check are provisional shells (§7.5, I-P markers).
- Co-effect declaration grammar, self-reference flagging, `apply`/`post_check` authoring surface beyond the three 001 §5 signatures → **006**.
- Fact canonicalization, `(batch_id, record_key, content_hash)` dedup, delta detection, the fold contract and its proof obligations → **007**. The commit stage leaves a named seam (`frames.delta_filter`, identity in Phase 1).
- `batch-completed` payload freeze, catalog stats, compaction/orphan-sweep of data tables → **008**. This LLD emits a provisional payload (§6.6) — derived from durable state, never from attempt-local scaffolding (I-19).
- `pipeline.yaml` authoring surface and pipeline IaC-from-yaml → **009**. This LLD defines only `PipelineSpec`, the *resolved value the runner consumes* (§6.2).
- `serialize: true` honoring mechanics (004 §16.2), EMR Serverless entrypoint (013), cross-materialization (011).

## 2. Decision Record

Decisions 004 left to the LLD, now pinned. I-numbers avoid collision with 004's D-numbers; cite as "004.1 I-n". I-19…I-24 were added in v0.2 from review findings.

| # | Decision | Choice | Rationale / trade-off |
|---|---|---|---|
| I-1 | Engine + interpreter pinning | **Glue 5.0**: Spark 3.5.x, **Python 3.11**, Iceberg 1.6.1 runtime. The spine package is `requires-python = ">=3.11"`; **CI runs spine tests under 3.11** even though the workspace default is 3.12. Exact pins verified against the Glue 5.0 release notes at M6 (checklist §13.1) and recorded in `pyproject.toml` comments. | D-7's zero-divergence claim ("CI runs the engine production runs") extends to the interpreter — a 3.12-only idiom that works in CI and dies on Glue is exactly the divergence D-7 paid CI-minutes to exclude. Cost: two Python versions in one workspace; `uv run -p 3.11 --package conveyer-spine` confines it to Makefile targets. |
| I-2 | Effect substrates | **Three, by channel**: Spark (Iceberg catalog `glue` prod / `hadoop` tests) for all data-path reads/writes; **driver-side pyiceberg** (`GlueCatalog` prod / `SqlCatalog` tests — 002.1 D-7's pattern) for run-ledger appends; boto3 for `PutEvents`. | A 1-row ledger append as a Spark job costs seconds × 8 stages × attempts; pyiceberg appends an Arrow table directly. The run ledger being on a *separate catalog client* from the data path is safe by design: correctness never reads it (004 §13.4). |
| I-3 | Guard mechanics | **Guards read data, never metadata**: `table_has_batch` = the negation of `spark.table(t).where(<batch predicate>).limit(1).isEmpty()`, where the predicate is built **from column objects and literals** (`F.col("batch_id") == F.lit(b)`), never by string interpolation [S-6]. Snapshot **summary properties** (`conveyer.batch-id`, `conveyer.stage`) are stamped on every commit — used for **lineage and own-commit resolution (I-19), never by guards**. | Snapshot history expires (30 d retention); a deliberate rerun months later would double-append if guards read snapshot metadata. The data outlives every snapshot. Scan cost is bounded by file pruning: each stage writes one batch in one commit, so a `batch_id` predicate prunes other batches' files via column stats (UUID prefixes survive the default 16-char stat truncation with ~60 bits of discrimination [T-9]). **Compaction dependency**: pruning cost and `read_batch` both assume rewrites preserve `batch_id` clustering — a registered 008 obligation (§15.2). **Soundness precondition**: check-then-append is sound only under **at most one live writer per `batch_id`** — see I-20. |
| I-4 | One-commit invariant, mechanically | A stage's write to a table is **exactly one `df.writeTo(t).append()` call or one `MERGE INTO` statement** — DataFrameWriterV2 commits once per call regardless of partition/file count. **Banned in the effects layer**: per-partition write loops, `foreachPartition` writes, chunked appends, more than one write call per (stage, table), `INSERT INTO` via repeated `spark.sql`. A kill mid-write leaves **zero commits** plus orphaned data files — invisible to guards (atomic), swept by 008's maintenance. (Spark's own write-abort cleanup will log S3 delete failures under the lake's delete-deny — harmless noise, runbook-noted [T-22].) | D-4's soundness condition made checkable: grep-level review rule + integration test asserting exactly one new snapshot per effectful stage (§12.4 R-13). |
| I-5 | Attempt identity in the run ledger | **`attempt_id` = the Glue job run id**, read from `--conveyer-attempt-id` when supplied, falling back to Glue's injected `--JOB_RUN_ID` [T-13]; `sfn_retry_count` / `sfn_redrive_count` carried as informational fields from the SFN context object. "Attempt N" ordinals are a **fold** over run rows ordered by `started_at`, computed at query time. | The ledger is deliberately lossy (004 §13.4); an ordinal *stored* in a lossy channel lies under loss. The engine's run id is ground truth that costs nothing. The explicit-override-with-fallback keeps EMR parity honest: the 013 submitter supplies `--conveyer-attempt-id` (I-14's claim is "same argv contract *plus submitter-supplied attempt identity*"). 004 §13.2's "(batch_id, attempt, stage)" reads `attempt := attempt_id` — errata §15.3. |
| I-6 | Pinned co-effect reads | `read_table` resolves the table's **current snapshot id first**, then reads **`AT` that snapshot** (`option("snapshot-id", sid)`), returning `(df, sid)`. Zero-snapshot table: explicit branch — unpinned read of the empty table, `sid = -1` recorded as the documented "existed, no snapshot" sentinel [T-19]. | Spark plans are lazy (004 D-2): an unpinned read may *execute* after a concurrent sibling's commit, making the recorded `co_effect_snapshot_ids` a lie about what `apply` actually perceived. Pinning makes recorded = perceived, at zero cost. (Cross-*attempt* pinning stays rejected — 004 §8; this pins within one attempt only.) |
| I-7 | Events are never guarded | `batch-started` and `batch-completed` are emitted **unconditionally on every attempt**, including attempts where every table write was guard-skipped. Tables are guarded; events are at-least-once; consumers dedup on `batch_id` (pattern per 002.1 D-14; the dedup keys for spine events are owned by 004 §9). `emit` **must inspect `PutEvents`' `FailedEntryCount` and raise `TransientError` on any failed entry** — boto3 does not raise for per-entry failures, and I-18's whole reduction rests on emit failures failing the job [T-17]. | A guarded emit loses the event forever when the process dies between commit and emit — the one gap a guard cannot close, because `PutEvents` leaves no presence to check. Uniform rule, no per-stage cases: **presence-guard what has presence; re-emit what doesn't.** Event *payloads* are a separate concern: they describe the batch, not the attempt, and are derived from durable state (I-19). |
| I-8 | Router shape | One **zip Lambda** (stdlib + boto3 only — no pyspark, no pydantic; enforced by an import test), one platform-level EventBridge rule for all pipelines; state-machine ARN resolved by naming convention `${p}-spine-<slug(pipeline)>` after validating `pipeline` against the slug grammar. Validation is **stdlib**: `batch_id` must match the UUIDv5 regex (I-22), `pipeline` the slug grammar, required fields present [E-3]. The router forwards a **minimal allowlisted projection** of the detail (the §6.1 v1 fields only — a stdlib dict comprehension), never the raw detail: `extra` fields from the bus must not ride into execution history and Glue argv [S-2]. Unknown pipeline / other errors → raise → Lambda retry → DLQ → alarm. `ExecutionAlreadyExists` → log INFO, metric `SingleFlightCollisions`, return success. (Note: `StartExecution` with same name **and byte-identical input** against a RUNNING execution returns 200 with the existing ARN — the most common duplicate never throws, so `SingleFlightCollisions` undercounts; detect "joined existing" by comparing the returned `startDate` if the count matters [T-20].) | Per-pipeline rules would still need the router (EventBridge cannot set a custom execution name — 004 §7.1); one rule keeps provisioning flat. A `delivery-registered` for an unprovisioned pipeline is an ops signal, not a silent drop. Full pydantic parsing stays job-side (§6.1) — the router validates only what it uses. |
| I-9 | A second pure zone: `frames/` | Dataframe-in/dataframe-out **pure plan builders** live in `spine/frames/` — linted with the *transforms* profile (pyspark allowed; effects, `SparkSession`, driver materialization banned). `spine/core/` stays plain-value pure (**no pyspark import at all**). `frames/` functions take **DataFrames and narrow plain values only** — never `BatchContext` (which they are linter-banned from importing): lineage inputs arrive as a `LineageStamp` frozen dataclass defined in `core/` [C-5]. | Default fold, violation subtraction, lineage stamping are pure logic *over plans* — they belong in neither `core/` (would drag pyspark into the value layer) nor `stages/` (would bury logic in orchestration). Two pure zones, one linter profile each. Layout accretion to 004 §10, errata-noted (§15.3). |
| I-10 | Transforms binding | The seed context carries `transforms: Transforms` — a frozen record of the pipeline's pure functions, built by `binding.bind_transforms(spec)` (importlib) in the entrypoint, **validated before `land`**: required exports present, signatures arity-checked, `fold` optional → default LWW. `transforms_module` must match `^pipelines\.[a-z0-9_]+(\.[a-z0-9_]+)*$` — imports resolve **only** inside the `pipelines.` namespace shipped in the pinned wheel [S-3]. Binding failure raises before any effect — no raw write, no `batch-started`, execution fails, alarm. | Functions are values; a record of them rides the context like any other seed value (002.1 §7.7 idiom). Fail-fast keeps a misconfigured pipeline from half-starting a batch; the namespace grammar keeps `importlib` from being an arbitrary-code loader. |
| I-11 | Fold mechanics (default LWW) | **Slice-fold + conditional upsert**: `touched` = distinct `domain_id`s in the batch's committed facts; `state_slice` = current state semi-joined to `touched`; `new_rows = fold(state_slice, committed_facts_df)` (custom or `frames.default_lww_fold`); MERGE INTO on `domain_id` with `WHEN MATCHED AND <src ordering struct> > <tgt ordering struct> THEN UPDATE, WHEN NOT MATCHED THEN INSERT`. Isolation stays **serializable**; the loser of a concurrent-sibling conflict surfaces as `ValidationException` (not internally retried), which — like surfaced `CommitFailedException` — maps to `TransientError` → job fails → SFN retries → converges under D-4. `CommitStateUnknownException` also maps to `TransientError`, and the rerun's normal presence/convergence path resolves the ambiguity [T-10]. **Ordering-struct semantics, pinned:** Spark struct comparison is field-wise lexicographic with **null fields ranking lowest** and strict `>` — so a null-keyed fact never displaces a non-null state row, ties never update (rerun-idempotent), and `content_hash` as final component makes the order total [T-11]. **Cardinality precondition:** a fold must emit **at most one row per `domain_id`**; violation is a deterministic MERGE cardinality error surfaced as a named defect [T-12]. The provisional ordering key `(event_time, source_ts, content_hash)` is **hardcoded inside `frames.default_lww_fold`** — deliberately *not* a `PipelineSpec` field; 007 owns the final key and decides whether it ever becomes a knob [C-4]. | The fold contract (idempotence, order-insensitivity) is 007's; the spine owns the *mechanics* any conforming fold runs through. The ordering-conditional MERGE is the belt on top of serializable isolation (004 §7.3.2). Row deletion is not expressible in Phase 1 — LWW never drops; named for 007. Do not narrow the isolation level: the loser is only *reliably* the loser because serializable's conflict detection is broad [T-10]. |
| I-12 | Violation subtraction | `admitted = candidate` anti-joined against violations on **all shared columns** — provisional; **006 owns violation identity** (a keyed subtraction). `violations_df` contract meanwhile: candidate columns + `reason: string`, nothing else, and violations must be a **multiplicity-preserving subset** of candidate rows [C-8]. **On the fresh-compute path** the stage asserts the count identity `candidate == admitted + violations` and fails the batch loudly on mismatch — until 006's keyed identity, this is what keeps a non-conforming `post_check` from silently dropping rows. **On post_check guard-skip (rerun), the subtraction uses the read-back durable quarantine rows for `(batch_id, "post_check")`, not the recomputed violations** — D-3's read-by-name applied to quarantine, so facts and quarantine stay complementary even when attempts perceive different co-effects [E-5] — and the count identity is **NOT asserted there** [H-2]: the rerun's candidate is recomputed under possibly-drifted co-effects while the violations are another attempt's durable rows, so the identity can fail *deterministically* and wedge a batch whose only remaining job is to re-announce (kill-after-commit-before-publish). The assertion's diagnostic value was delivered on the attempt that computed both sides fresh; on read-back the stage verifies the subset property and surfaces a mismatch **as data** — WARNING log + EMF `PostCheckDrift` + the ledger row's `error_message` field on an `ok` outcome — never as failure. | All-column anti-join is correct for deterministic transforms and requires no key invention this doc has no authority to do. The residual cross-attempt incoherence (quarantine reasons reflect attempt N's perception, facts attempt M's) is named in §9 and proposed as a 004 §8 erratum. |
| I-13 | Single-flight test substrate | **Stub, not deployed**: router unit tests run against a record-of-functions SFN double (two duplicate events → exactly one `start_execution` + one `AlreadyExists`-swallowed); a **declared-invariant test** asserts the execution name is byte-equal to `batch_id` and that the deliberate-rerun grammar `^<batch_id>--r[0-9]+$` cannot collide with it — which the `batch_id` UUIDv5 pattern (I-22) makes *structurally enforced*, not merely tested [S-2]; the deployed smoke (M6) exercises the real chain once. | moto's SFN cannot run `glue:startJobRun.sync` anyway; the property that needs proving — name = batch_id, duplicate collides, `AlreadyExists` = success — is router logic plus an AWS-documented API contract (names unique for 90 d), not emergent behavior. |
| I-14 | Engine-agnostic entrypoint | **No `awsglue` import anywhere in `spine/`** (linter-banned). Job arguments are parsed from plain `argv` by a pure function (`core/args.py`); the SparkSession is built from explicit catalog conf, not `GlueContext`. The EMR Serverless entrypoint (013) becomes: same wheel, same `argv` contract **plus submitter-supplied `--conveyer-attempt-id`** (I-5) [T-13], different submitter. Glue-specific operational couplings are named, not hidden: EMF-via-continuous-logging (§11.1, M6-verified [T-14]) and `--JOB_RUN_ID` fallback. | 004 §16.4 asks 004.1 to *keep parity visible*; the cheapest visibility is structural absence of the Glue-only API plus an explicit list of what the next engine's submitter must provide. |
| I-15 | Linter promotion shape | `ingestion/tools/purity_linter.py` moves to repo-root **`tools/purity_linter.py`**; rule tables become fields of a frozen `LinterConfig`; per-package configs are data modules (`tools/linter_configs/ingestion.py`, `tools/linter_configs/spine.py`) selected by CLI arg. Ingestion's current rules (including its hardcoded exemptions) transfer **verbatim** — its suite must stay green through the move (M0 gate). Three spine profiles: `core` (ingestion-core rules + `pyspark` ban), `frames`/transforms (§12.3), idiom-everywhere. | One implementation, N configurations (004 D-8). Config-as-data keeps the linter itself free of package knowledge. |
| I-16 | Contract fixtures | Repo-root **`contracts/fixtures/events/<detail-type>/<case>.json`** — full EventBridge `Detail` payloads, concrete values. Producer side (ingestion): construct the event from pinned inputs, assert **exact JSON equality** with the fixture. Consumer side (spine): parse every fixture file in the directory, assert semantic fields. Both suites glob the same directory; a fixture change is a PR that touches both packages' expectations or fails CI. | 004 D-13 made the seam JSON-on-the-wire; exact-equality on the producer keeps "accidentally additive" changes loud, and parse-everything on the consumer keeps tolerant-reader honest. |
| I-17 | Run-ledger maintenance & retention | Weekly Athena `OPTIMIZE` + `VACUUM`, **piggybacked on ingestion's maintenance Lambda** (002.1 §9.4) via one additive config entry (list of tables it sweeps) **plus one prefix extension of the maintenance role's S3 delete grant: exactly `${p}-lake/spine/run_ledger/*`, never a `${p}-lake/*` wildcard** [E-7, S-12]. Table properties at bootstrap: `vacuum_max_snapshot_age_seconds = 2592000` (30 d), `vacuum_min_snapshots_to_keep = 5` (the Athena-property trap 002.1 §9.4 documents), **and `write.metadata.delete-after-commit.enabled = true` + `write.metadata.previous-versions-max = 20`** — per-transition pyiceberg commits accrete metadata.json files that VACUUM does not remove [T-18]. **Rows are kept indefinitely** in Phase 1 — the run ledger is audit, rows are tiny. | A second maintenance Lambda would duplicate a working pattern for one more table name. The coupling (spine depends on an ingestion-owned scheduler) and the grant extension are both named here so they exist in IAM review, not just a table list. The run ledger is *written by the audited principal and prunable by an ingestion-owned role* — fine for a deliberately lossy ops channel; it must never be cited as a compliance-grade audit trail [S-12]. |
| I-18 | Stuck-batch alarming | The 004 §13.4 "batch-started without batch-completed inside SLA" alarm **reduces to SFN execution alarms**: `publish` runs inside the job and `emit` failures raise (I-7 — including partial `PutEvents` failures [T-17]), so *execution `SUCCEEDED` ⟹ `batch-completed` emitted (at-least-once)*; a stuck batch is therefore exactly a failed or timed-out execution. **Timeout arithmetic** [T-2, E-11]: `sla_minutes` is the **per-attempt** budget — Glue job `Timeout = sla_minutes`; SFN `TimeoutSeconds = (MaxAttempts + 1) × sla_minutes × 60 + 900` (margin for backoff + `.sync` polling lag) — so `ExecutionsTimedOut` genuinely means "retries exhausted by time", never "healthy retry killed mid-run". | No scheduled ledger-scanning machinery in Phase 1. The reduction argument is stated here and must be re-checked if publish ever moves out of the job, or if `emit` stops raising on partial failure. |
| I-19 | Own-commit resolution; event payloads from durable state | **Never read "current" to learn about your own commit** [T-3]: under D-12, siblings commit to the same tables between your commit and any "current snapshot" probe. `fx.append` resolves its own snapshot by the stamped `conveyer.batch-id`/`conveyer.stage` summary properties (walk `snapshots` newest-first) and returns `(snapshot_id, summary)`; write-side **counts come from the commit's own summary** (`added-records`), not from re-counting DataFrames — a `.count()` on a post-transform df re-executes the whole upstream DAG [T-6]. `fx.merge` captures `before_id` pre-commit and identifies its snapshot as the unique child of `before_id` (valid *because* isolation is serializable — stated reliance); an unchanged snapshot id after MERGE is an explicit **no-op result** (`rows_merged = 0`, no fabricated snapshot) — the healthy-rerun MERGE updates nothing and may commit nothing [T-4]. **Event payloads describe the batch, not the attempt** [E-1, T-1]: `publish` (and `land` for `batch-started`) derive counts and snapshot ids from durable state — read-backs by `batch_id` and stamped-summary resolution — never from attempt-local accreted deltas, which exist for the *ledger's* per-attempt story. On guard-skipped stages the stamped summary recovers the original commit's snapshot id (lineage use, permitted by I-3); after 30 d snapshot expiry the id degrades to `None`, documented. | One mechanism closes four review findings: wrong-snapshot lineage under concurrency, double-execution of the heavy path for counts, fabricated fold snapshots on no-op reruns, and the rerun-as-announcer emitting a false `batch-completed` (which also violated D-3's letter — "fold **and publish** consuming committed facts by name"). The ledger's `facts_appended = 0, skipped-guard` rerun signature is untouched — attempt-truth and batch-truth are now two separately-sourced values instead of one complected field. |
| I-20 | Single-writer-per-batch invariant | D-4's check-then-append guards are **sound only while at most one live writer exists per `batch_id`** — the guard window spans a whole stage's compute, not microseconds. D-10's single-flight provides this for the event path; **two escape hatches reintroduce concurrency and are governed, not ignored** [C-3, E-2]: (a) *zombie attempts* — SFN can consider a `.sync` task failed while the Glue run still lives. The `.sync` integration issues `BatchStopJobRun` when the task is **cancelled** (execution stop/timeout — the reason the role holds that grant), but **not** on the misperceived-failure path, where SFN believes the run already died; and `max_concurrent_runs` cannot close the gap — it is per-*job*, sized > 1 precisely so D-12's parallel *different*-batch runs work, so a zombie plus its same-batch retry is 2 runs and nothing fails loudly [H-3]. Phase 1 accepts this as a **rare named residual** (the window requires SFN to misperceive a live run as dead, and the blast radius is the bounded one below); true abort-then-retry — a `Catch` → `BatchStopJobRun` → re-enter loop in the state machine — is deferred machinery, recorded here so it is deferred knowingly; (b) *operator `--rN` runs* — the runbook precondition (§10.6) requires `describe-execution` terminal **and** no RUNNING job run for the batch before starting one. Residual blast radius if violated: duplicate raw/quarantine/fact rows for one batch (append-append does not conflict); current state still converges for conforming folds (duplicate identical facts tie on the ordering key). Proposed as a 004 D-10 erratum: "both safe under D-4" carries this precondition (§15.3). | Naming the premise is what makes the escape hatches reviewable. A CAS-shaped guard (conditional commit on absence) does not exist in Iceberg appends; the honest alternative is governing writer liveness, which the orchestrator already owns (D-10's own logic). |
| I-21 | Per-pipeline job IAM | The Glue job role is created **in `modules/spine-pipeline`, one per pipeline** — not a shared platform role [S-4]: landing read scoped to the feeds routed to *this* pipeline; lake access scoped to `${p}-lake/tables/<slug>/*` + `${p}-lake/spine/run_ledger/*`; Glue catalog grants **per-table** (`<slug>__*` + `run_ledger`), never database-wide — `glue:UpdateTable` on another pipeline's table is a metadata-pointer attack that swaps table contents with no S3 write [S-5]; co-effect tables get read-only grants **generated from `spec.co_effects`**, so reading another pipeline's data is a provisioning event, not a YAML edit [S-15]. No spine role holds any delete permission, any grant under `${p}-lake/ledger/*` (ingestion's ledger is unreachable even under a misconfigured spec), or `glue:CreateJob`/`UpdateJob`/`DeleteTable`. | Restores the blast-radius wall 002.1 §10.7 built: pipeline-author code (CI-linted, but code) runs with authority over exactly its own lane. Platform-level wildcards were a placement error — the resources are per-pipeline, so the role must be. |
| I-22 | Event trust boundary | The seed is validated as a **narrow** type, not merely parsed [S-1, S-2]: `batch_id` must match the UUIDv5 pattern (which also makes `--rN` names unreachable from the event path); `object_uris` is capped (≤ 256 URIs, each ≤ 1024 chars) and **every URI must match the canonical landing shape for this delivery's own identity** — `s3://<landing_bucket>/<feed_id>/received_at=…/dl-<delivery_id>/<name>` — before `read_objects` may see it; a failure is a binding defect (fail-fast pre-land, I-10 class). The bus itself gets a **resource policy**: `events:PutEvents` only for the ingestion producer roles and the spine job role, each **conditioned on the `events:source` value it owns** (`conveyer.ingestion` / `conveyer.spine`). | Without this, any in-account `PutEvents` principal can poison append-only tables via forged `object_uris` (unrepairable by construction) or **squat a future legitimate `batch_id`** — the router treats `ExecutionAlreadyExists` as success, so the real delivery would be silently swallowed. Self-consistency validation costs one regex per URI and closes the whole class: the event can only name the delivery it is. |
| I-23 | Artifact supply chain | The wheel key is **content-addressed and immutable**: `s3://${p}-artifacts/spine/<git-sha>/conveyer_spine-….whl`; Terraform pins the exact key; `${p}-artifacts` gets versioning plus a bucket-policy deny of `PutObject`/`DeleteObject*` under `spine/*` for all but the deploy principal. `--python-modules-installer-option "--no-index"` with the full transitive set pinned (or bundled-version reuse where Glue 5.0 ships the dep) — a job start never resolves from PyPI [S-3, T-15]. `--conveyer-pipeline-spec-uri` is validated in the entrypoint against `s3://${p}-artifacts/spine/specs/<this job's slug>/`; the job role reads `${p}-artifacts/spine/*` and nothing else in that bucket. **Argv is a trust boundary**: `StartJobRun.Arguments` override job defaults including `--additional-python-modules`, so `glue:StartJobRun` on a spine job *is* code execution as the job role — held by the `spine-sfn` role only. | Three previously-independent RCE paths (mutable wheel, arbitrary `transforms_module`, unvalidated spec URI) converge on a role holding lake write; each link is pinned. Mirrors ingestion's own `IMMUTABLE` ECR decision (002.1 §10.5) for the artifact this package actually ships. |
| I-24 | Structural fact check at commit | Before the fact append, a **pure structural check** (in the commit planner) verifies: `domain_id_col` non-null on every row, and the fact schema matches the target table (a pure column-set diff — so drift fails as a named defect before burning SFN retries on `AnalysisException` [E-18]). A NULL `domain_id` is a **fail-fast defect**, not a quarantine row: MERGE's `ON` clause never matches NULL, so such a row would be **re-INSERTed by every fold rerun** — fold has no guard, and rerun-is-a-no-op (the phase gate) would be silently false [E-6]. 007 may later demote specific cases to quarantine; the spine's floor is "no silent convergence break". | The check is cheap (one aggregate over a column + a schema diff), deterministic, and protects the single invariant the whole design stands on. |

## 3. System Overview

### 3.1 Components and runtimes

| Component | Runtime | Trigger | Role (flow vocabulary) |
|---|---|---|---|
| **Router** | Lambda (zip, stdlib+boto3), framework-owned, one function | EventBridge rule on `${p}-bus`: `source = conveyer.ingestion`, `detail-type = delivery-registered` | *route*: event → named SFN execution; wiring only (004 §7.1) |
| **State machine** | Step Functions **Standard**, one per pipeline | `StartExecution(name = batch_id, input = allowlisted detail)` | single-flight + whole-job retry unit (004 D-1, D-10) |
| **Runner job** | Glue 5.0 Spark job, one per pipeline, same wheel, `max_concurrent_runs` > 1 (D-12; §10.4) | `glue:startJobRun.sync` from the state machine | the eight stages over one `BatchContext` |
| **Run ledger** | Iceberg table `<spine db>.run_ledger` on S3 | — | the run reified as data (004 D-11) |
| **Identity exemplar** | test asset inside `spine/tests/` + one deployed instance | CI + deployed smoke | proves the spine with zero domain logic |

Structural note [E-17]: the event carries one `pipeline` per delivery (002.1 §6.4), so one feed → one pipeline **by construction**; fan-out to a second pipeline over the same feed requires an upstream contract change, not a spine change.

### 3.2 Flow

```
delivery-registered on ${p}-bus  (bus policy: producers only, I-22)
  ─▶ rule ─▶ router λ
        stdlib-validate: batch_id UUIDv5, pipeline slug grammar, fields present (I-8)
        slug = slugify(detail.pipeline)          # injective grammar, §5
        StartExecution(sm = ${p}-spine-<slug>, name = detail.batch_id,
                       input = allowlisted v1 fields)
          ExecutionAlreadyExists ─▶ INFO + metric, done          # single-flight, D-10
  ─▶ SFN: one Task state, glue:startJobRun.sync, Retry ×2 (whole job, D-1; abort-then-retry, I-20)
  ─▶ glue_main.py: parse argv → RunnerConfig + seed (full pydantic + I-22 checks) →
        bind transforms (I-10) → SparkSession → fx → spine.run(seed, fx)
        land → pre_check → pull → apply → post_check → commit → fold → publish
        each transition: fx.record_run(run_fact)   # best-effort, never gates (004 §13.4)
  ─▶ batch-started (after land), batch-completed (publish) on ${p}-bus  (payloads: I-19)
```

### 3.3 What never happens here (inherited invariants)

No serialization of the context (004 D-2); no durable mid-flight state — the fact table is the only checkpoint (D-3); no deletes or rewrites on any data path — appends and MERGE only; no instrumentation inside stages (D-11); no pipeline-code access to `BatchContext`/`RunnerFx` (D-9); no control decision reads the run ledger (004 §14.7); **no telemetry carries row data** (§6.5 / §11.2 rule [S-7]).

## 6. Contracts and Data Model

All boundary contracts are pydantic v2 models in `spine/core/model.py`; internal values are frozen dataclasses (002.1 §7.0, restated as law for `spine/` by 004 §10). `make -C spine schemas` exports JSON Schema; drift-checked in CI like 002.1 §6. **Parse, don't validate — with narrow types**: a parsed field the design later trusts (a name, an id, a URI) carries a pattern, a bound, or a shape check; "it parsed as `str`" is not trust [S-2 systemic note].

### 6.1 Seed event — spine-side `DeliveryRegisteredV1`

The spine owns its **own** model of the event (004 D-13 — no shared code, fixtures keep both sides honest):

```python
BATCH_ID_RE = r"^[0-9a-f]{8}-[0-9a-f]{4}-5[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$"  # UUIDv5, I-22

class DeliveryRegisteredV1(BaseModel):        # parse of SFN execution input
    model_config = ConfigDict(extra="allow")  # tolerant reader; unknown fields ignored
    schema_version: Literal[1]
    feed_id: str = Field(pattern=r"^[a-z0-9][a-z0-9-]*/[a-z0-9][a-z0-9-]*$")
    delivery_id: str = Field(                  # participates in the I-22 URI/name composition,
        pattern=r"^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$"
    )                                          #   so it is narrow-typed like batch_id [H-4]
    batch_id: str = Field(pattern=BATCH_ID_RE)
    delivery_key: str
    content_hash: str                          # OPAQUE lineage here (004 D-13); never parsed
    size_bytes: int
    object_uris: list[str] = Field(min_length=1, max_length=256)   # each ≤ 1024 chars, I-22
    received_at: AwareDatetime
    pipeline: str                              # slug grammar re-checked at parse
```

After the parse, the entrypoint runs `naming.check_object_uris(seed, config)` — every URI must match the canonical landing shape **for this delivery's own `feed_id` and `delivery_id`** in the configured landing bucket (I-22); failure is a binding defect (fail-fast pre-land). `min_length=1` is stricter than 002.1 §6.4's producer model; registration guarantees ≥ 1 data object by construction — recorded as a 002.1 errata note plus a fixture, §12.6 [E-12]. Parse failure → raise → job fails → SFN retry → alarm.

```python
    started_at: AwareDatetime                  # ATTEMPT-truth — declared exception [H-1], see below

class BatchCompletedV1(BaseModel):             # PROVISIONAL — 008 owns and freezes the payload
    schema_version: Literal[1] = 1
    pipeline: str; feed_id: str; batch_id: str; delivery_id: str
    raw_count: int; pre_quarantined: int; post_quarantined: int   # read-back by (batch_id[, stage])
    fact_count: int                            # count of committed_facts_df — batch truth [E-1].
                                               # Named fact_count, NOT facts_appended: the ledger's
                                               # facts_appended is an ATTEMPT delta (0 on guard-skip);
                                               # one identifier must not carry two sourcings [H-1]
    fact_snapshot_id: int | None; state_snapshot_id: int | None   # None: expiry / fold no-op
    completed_at: AwareDatetime                # ATTEMPT-truth — see below
```

Both at-least-once, unconditional per attempt (I-7); consumers dedup on `batch_id` (004 §9). A rerun's re-emission carries the **same batch-level values** as the original would have — that is the point of I-19. **Declared exception [H-1]: `started_at` and `completed_at` are attempt-truth** — `fx.now()` has no durable source (the ledger cannot supply one without violating §14.7's no-control-reads rule, and snapshot timestamps don't exist for no-op folds or empty batches), so a rerun's emission carries its own clock. Consumers gate and dedup on `batch_id`; the timestamps are informational. R-02 asserts payload equality **excluding these two fields**.

### 7.3 `run.py` — the sequence driver

```python
STAGES: tuple[tuple[str, StageFn], ...]        # (("land", land.run), …, ("publish", publish.run))

def run(seed: BatchContext, fx: RunnerFx) -> BatchContext:
    ctx = seed
    for name, stage in STAGES:
        t0 = fx.now()
        try:
            nxt = stage.run(ctx, fx)
        except BaseException as e:
            fx.record_run(run_facts.failed(name, ctx, t0, fx.now(), e))   # best-effort
            raise                                                          # whole-job retry, D-1
        fx.record_run(run_facts.transition(name, ctx, nxt, t0, fx.now()))
        ctx = nxt
    return ctx
```

Stages contain **zero** instrumentation (004 §13.3); `core/run_facts.py` derives each `RunFact` purely from `(stage, ctx_before, ctx_after, t0, t1)` — outcome `skipped-guard` iff `stage ∈ ctx_after.guard_skips \ ctx_before.guard_skips`; counts/snapshot fields read off the accreted deltas; `error_message` derived per §6.5. Channel ordering inside `fx.record_run`'s implementation [C-6, E-15]: **the INFO transition line and EMF metrics are emitted first, unconditionally; the ledger append is attempted last** under a small time-boxed budget — the lossy channel must never degrade the two that back it up.

### 7.5 Stages — normative algorithms

Every stage is `run(ctx, fx) -> BatchContext` (004 §6.1); every table write follows decide-then-do through `core/guards.py`:

`frames/` receives lineage as a value, never the context [C-5]:


**land** — ① `present = fx.table_has_batch(spec.raw_table, batch_id)`; ② if absent: `df = fx.read_objects(ctx.object_uris, spec.read)` *(provisional reader, I-P1: CSV, UTF-8, header row, all columns string, Spark CSV **`mode=FAILFAST`** — undecodable/malformed bytes are a deterministic job failure in Phase 1; real unreadable-row semantics are 004 §16.3 → 005)*; `raw = frames.stamp_raw_lineage(df, stamp)`; `(land_snapshot_id, summary) = fx.append(raw_table, raw)` else accrete `guard_skips + ("land",)` and resolve `land_snapshot_id` by stamped summary (I-19). ③ `raw_df = fx.read_batch(raw_table, batch_id)` — read back by name even when this attempt wrote it (one code path). ④ `raw_count`: from the append summary's `added-records` when this attempt wrote; from `raw_df.count()` on guard-skip (the one deliberate action on this path) [T-6]. ⑤ `fx.emit("batch-started", …)` — **unconditional** (I-7), payload per I-19.

**pre_check** — `viol = frames.pre_violations(ctx.raw_df, spec.required_columns)` *(provisional, I-P2: rows with nulls in required columns; 005 owns the contract grammar)*; `valid_df` and `viol` derived from the **same predicate** — deterministic, co-effect-free, so rerun-recomputation is consistent with durable quarantine rows by construction (a standing constraint handed to 005: pre_check must remain co-effect-free for this to stay true [E-5 note]); quarantine rows = `frames.shape_quarantine(viol, stamp, check_stage="pre_check")`; guarded append keyed `(batch_id, "pre_check")` (004 §8 two-writer note); counts from the append summary; snapshot accretes. Zero violations ⇒ no write, no guard row — naturally idempotent (004 §8 zero-write note).

**pull** — for each `(name, decl)` in `spec.co_effects`: `(df, sid) = fx.read_table(decl.table)` (pinned, I-6); `decl.own_state and not spec.serialize` ⇒ WARNING log (Phase 1 honoring gap, 004 §16.2). Accrete both maps. Reads only; rerun drift is harmless per D-3.

**apply** — `candidate = ctx.transforms.apply(ctx.valid_df, ctx.co_effects)`. Pure; nothing else. (The df handed to `apply` is `valid_df` — 001 §5's `raw_df` argument *post-admission*; stated here once.)

**post_check** — `viol = ctx.transforms.post_check(ctx.candidate_facts_df, ctx.co_effects)`; contract per I-12, count-identity **asserted on the fresh-compute path only** [H-2]; quarantine shaped + guarded append keyed `(batch_id, "post_check")`. **If the guard indicates rows already present** (rerun): the subtraction's violation set is the **read-back durable quarantine rows** for `(batch_id, "post_check")`, not the recomputed `viol` — facts and quarantine stay complementary across attempts (I-12) [E-5] — and a subset/count mismatch is recorded as data (WARNING + `PostCheckDrift`), never raised (I-12 [H-2]).

**commit** — `present = fx.table_has_batch(spec.fact_table, batch_id)`; if absent: `stamped = frames.stamp_fact_lineage(ctx.admitted_facts_df, stamp)`; **structural check** (I-24): non-null `domain_id`, schema diff vs fact table — violation = named defect, fail fast; `to_append = frames.delta_filter(stamped)` — the **named 007 seam, identity in Phase 1**; `(fact_snapshot_id, summary) = fx.append(fact_table, to_append)`; `facts_appended` = summary `added-records`. On guard-skip: `facts_appended = 0` (the ledger's healthy-rerun signature), `fact_snapshot_id` resolved by stamped summary (I-19). `committed_facts_df = fx.read_batch(fact_table, batch_id)` (D-3 — candidates are dead).

**fold** — `touched = ctx.committed_facts_df.select(domain_id).distinct()`; `(state_df, state_read_snapshot_id) = fx.read_table(spec.state_table)`; `state_slice = state_df` semi-joined to `touched` (a plan); `new_rows = ctx.transforms.fold(state_slice, ctx.committed_facts_df)`; `spec_m = core.merge.merge_spec(spec, new_rows.schema)` (identifier validation, §6.7); `result = fx.merge(spec_m, new_rows)` → own snapshot + summary, or explicit **no-op** (I-19) → `state_snapshot_id = None`, `rows_merged = 0`. Empty `committed_facts_df` ⇒ skip the merge entirely. No presence guard — idempotence is the fold contract (004 §8); the healthy rerun's MERGE updates nothing (strict ordering inequality) and reports no-op.

**publish** — build `BatchCompletedV1` **from durable state** (I-19): `fact_count = committed_facts_df.count()` [H-1]; quarantine counts read back by `(batch_id, stage)`; snapshot ids from accreted values (which are themselves durable-resolved); timestamps attempt-truth by declaration (§6.6). `fx.emit` **unconditional** (I-7); accrete `published`, `completed_event`. Catalog stats/compaction: **not here** — 008.

- **`table_has_batch`**: per I-3; predicates from column objects only.
- **`merge`**: temp view (fixed name) + one rendered `MERGE INTO` (§6.7); `before_id` captured pre-statement; own snapshot = unique child of `before_id`, else no-op result (I-19). - **`resolve_batch_snapshot`**: newest-first walk of the table's snapshot log matching `conveyer.batch-id` (+ stage); `None` when expired. Lineage-only by contract — a guard calling it is a review defect (I-3).
- **`record_run`** (`effects/ledger.py`): emits the INFO line + EMF metrics first (§7.3); then a pyiceberg append of a one-row Arrow table under a **time-boxed budget: 2 attempts, ≤ 2 s total backoff** [C-6] — the 002.1 ledger's 5×/8 s policy belongs to a system of record, which this channel deliberately is not; on exhaustion **log the row at WARNING (with `error_message` omitted [S-7]) + EMF `RunLedgerLoss` and return**.
- **`emit`** (`effects/events.py`): `PutEvents` to `${p}-bus`, source `conveyer.spine`; **any exception or any `FailedEntryCount > 0` → `TransientError`** [T-17].

## 9. Failure & Idempotency — Implementation Map

004 §8's table, at implementation grain. Restart is always from stage 1 (D-4); everything below is what makes that convergent. Standing premise: **at most one live writer per `batch_id`** (I-20).

| Kill point | Durable trace | Rerun behavior |
|---|---|---|
| before land's append commit | none (orphan data files possible, invisible — I-4) | full re-execution |
| after land commit, before `batch-started` | raw rows present | land guard-skips; `batch-started` still emitted (I-7) with durable-derived payload (I-19) |
| after any quarantine/fact append | rows present with `(batch_id[, stage])` | guard-skip; `skipped-guard` ledger row; snapshot id recovered via stamp (I-19) |
| mid-MERGE | no commit (atomic) | fold re-runs; fold contract converges |
| after fold, before publish | state merged | land…fold all no-op/converge; publish emits — the rerun is *the* announcer, and its batch-truth fields equal the original's because they are durable-derived (I-19) [E-1]; only the declared attempt-truth timestamps differ (§6.6 [H-1]) |
| after publish, SFN retry anyway (e.g. sync-polling hiccup) | everything present | all guards skip, both events re-emitted with identical payloads, consumers dedup |

Edge cases, pinned:

- **Zero-row raw / all-quarantined batch**: flows to completion; `facts_appended = 0`; fold skips merge (`state_snapshot_id = None`); `batch-completed` carries the zero counts (R-09). Guards can't distinguish "wrote zero" from "never wrote" and don't need to (004 §8).
- **Merge conflict from a concurrent sibling** (004 §7.3.1): `ValidationException` (or surfaced `CommitFailedException`) → `TransientError` → job fails → SFN retry re-runs from land (all guard-skips) → fold retries with fresh snapshot [T-10]. Cost: one wasted job pass; accepted at Phase-1 volumes.
- **Cross-attempt perception drift** (004 §8's named trade-off, sharpened [E-5]): attempts may quarantine different rows at post_check than the attempt that committed facts. The durable pair stays complementary because the subtraction on rerun reads the durable quarantine (I-12); the *residual* incoherence — quarantine reasons reflect one attempt's perception, facts another's — is accepted and proposed as a 004 §8 erratum note (§15.3).
- **Duplicate `delivery-registered` weeks later**: SFN execution names are unique for ~90 days → `AlreadyExists` (or idempotent-success while RUNNING [T-20]) → router success. Beyond the name-retention horizon a duplicate starts a job whose every stage guard-skips and whose events re-emit with identical payloads. Both paths converge; neither is special-cased.
- **`--rN` rerun**: new execution, same `batch_id` seed → guards make it a no-op — **preconditioned on writer liveness** (I-20, runbook §10.6).
- **Config/binding/seed-validation defect**: raises pre-land (I-10, I-22) — no raw write, no `batch-started`, no ledger rows (run.py never entered); the failure surface is the SFN execution + alarm. Named limitation: such attempts are invisible to the run ledger; acceptable because they leave no data-path trace to audit.
- **Schema drift** (transform output vs fact/state table): caught as a named defect by the commit structural check (I-24); state-side mismatches surface at the MERGE render's identifier validation (§6.7). Deterministic and loud; additive-only evolution means tables evolve via 007/009 DDL, never via write-time merge-schema [E-18].
- **NULL `domain_id`**: fail-fast defect at commit (I-24) — the one input that would silently break fold convergence.
- **`record_run` loss**: never fails the batch (004 §13.4); WARNING log carries the row (message-stripped); `RunLedgerLoss` alarms at ≥ 1/h.
- **Orphan files** from killed writes: swept by 008's maintenance design (obligation §15.2); harmless meanwhile — never visible to any snapshot. (Runbook note: Spark write-abort delete attempts will log S3 AccessDenied under the delete-deny — expected noise [T-22].)

## 11. Observability

### 11.1 Metrics — EMF

Hand-rolled EMF dict printed to stdout (002.1 §11.2 idiom) from `record_run`'s implementation and the router; extracted by CloudWatch from the continuous-logging log group. **M6 must assert extraction end-to-end** — Glue's log pipeline can prefix lines, which silently kills every EMF metric and the alarms built on them; if prefixed, configure a bare-layout logger, with `PutMetricData` from the effects layer as the named fallback [T-14]. Namespace `Conveyer/Spine`, dimensions `pipeline`, `feed_id` (+ `stage` on stage metrics): `BatchesStarted`, `BatchesCompleted`, `StageSeconds`, `RawRows`, `QuarantinedRows` (dim `stage`), `FactsAppended`, `RowsMerged`, `GuardSkips`, `RunLedgerLoss`, `SingleFlightCollisions`, `JobAttempts`, `PostCheckDrift` (I-12 [H-2]).

### 11.2 Logs

Structured JSON via the 20-line stdlib formatter (002.1 §11.1); every record carries `batch_id`, `pipeline`, `feed_id`, `attempt_id`, `stage` when known. One INFO line per stage transition (from `record_run`, emitted before the ledger attempt — §7.3); WARNING for ledger loss and `own_state`-without-serialize; DEBUG for effect operations. **No log record at any level may contain DataFrame contents or row values** [S-18] — counts, ids, and snapshot ids only; `error_message` handling per §6.5. Spine log groups (router + Glue continuous logging) are created explicitly with 30 d retention.

### 11.3 Run ledger

Written per §6.5/§7.6. The non-gating rule (004 §13.4) is implemented as: `record_run` catches **everything**, logs, counts, returns — with the channel ordering of §7.3 (log + metrics before the lossy append). A lint-adjacent review rule: no call site of `record_run` sits inside the data path's error handling — it is fire-and-forget from `run.py` only.

### 11.4 Alarms (thresholds — the 004 §13.4 obligation)

| Alarm | Threshold | Window |
|---|---|---|
| Router errors / DLQ visible | ≥ 1 | 5 m |
| Per-pipeline `ExecutionsFailed` | ≥ 1 | 5 m |
| Per-pipeline `ExecutionsTimedOut` (retries exhausted by time — stuck batch, I-18) | ≥ 1 | 5 m |
| `RunLedgerLoss` | ≥ 1 (revisit rate-based once real concurrency exists [T-18]) | 1 h |
| Quarantine rate: `QuarantinedRows / RawRows` (metric math, per pipeline) | > 0.05 default, per-pipeline override (009) | 1 h |
| `JobAttempts` per pipeline (storm throttle signal [S-13]) | > 10 | 1 h |

### 11.5 Athena named queries (004 §13.2's four, concretized)

`spine-run-status` (latest outcome per (batch, stage) — fold ordered by `started_at`), `spine-attempts-per-batch` (distinct `attempt_id` counts, flags > 1), `spine-stage-durations-30d` (p50/p95 `finished_at - started_at` by stage), `spine-rerun-noop-rate` (share of attempts whose every row is `skipped-guard` with `facts_appended = 0` — 003's phase-gate criterion as a standing query).
