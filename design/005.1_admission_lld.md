## 1. Purpose, Scope, Non-Goals

Discharges every obligation 005 assigns to 005.1: the `RawContract`/`ReadSpec` runner models replacing I-P1/I-P2 (005 §13.1), corrupt-record capture under the chosen reader, deterministic per-object `row_index`, canonical JSON for `row_snapshot` + the `row_hash` algorithm, the two `unreadable/…` snapshot structures and the U+FFFD-on-`malformed_text` question, and raw/quarantine partitioning and table properties (005 §13.3) — plus the 004.1 §15.2 admission register and errata-notes §2 items (reader semantics beyond FAILFAST; the quarantine one-shape precondition of I-12; partner-filename classification).

**In scope (build all of this):**

1. **Contract models** — `ReadSpecModel`, `RawContractModel`, `ColumnSpec`, the type grammar, content-hash versions; `PipelineSpecModel` migration off `required_columns`/`read`.
2. **The reader** — per-object acquisition (decode ladder, header binding, locator assignment), the pure line parser in `core/`, the rewritten `fx.read_objects`.
3. **Production DDL** — raw and quarantine schemas, `identity(batch_id)` partitioning, the idempotent bootstrap with additive-only evolution, test-substrate parity.
4. **`pre_check`** — contract compilation to Spark expressions, one-evaluation-two-outputs, the typed projection, reason shaping, and the read-back-subtraction rerun path with the drift probe.
5. **Canonical JSON + `row_hash`** — one `core/` implementation, the UDF seam, shared vectors for 007.
6. **Quarantine one-shape** — `frames/quarantine.py` rewrite and the post_check writer/rerun changes it forces (interim, 006-registered).
7. **Exemplar migration, fixtures, A-suite tests, linter-config deltas, runbook/bootstrap wiring.**

**Out of scope (do not build):**

- `post_check` authoring surface, business-rule semantics, cross-field checks, final violation identity → **006** (the §8.2 mechanics land here as interim).
- Dedup, delta detection, ordering, fact canonicalization → **007** (receives §7.4 vectors; `frames.delta_filter` untouched).
- Payload freeze, compaction/orphan sweep, partition-cardinality review → **008**.
- Authoring file format/home for contract + read spec; IaC-from-yaml; per-feed thresholds → **009** (inherits the 005 §13.1 obligation to decide the surface afresh, not ratify §3's parse models).
- Remediation workflow, queue views, taxonomy governance → **012 / Track C**.
- The seed spill path (manifest-URI indirection, [T-5]) — needs a 002.1 producer change; carried in §15.2, not built.
- New format readers (fixed-width, JSONL, EBCDIC), charsets beyond utf-8, zstd — reserved grammar values (§3.1), added per 005 §5.5 when a resident feed needs them.

## 2. Decision Record

Decisions 005 left to the LLD, now pinned. A-numbers avoid collision with 005's D-numbers and 004.1's I-numbers; cite as "005.1 A-n".

| # | Decision | Choice | Rationale / trade-off |
|---|---|---|---|
| A-1 | Own the parse verdict | The reader acquires **decoded lines** via Hadoop text (one split per object, §5.1) and parses each line with a **stdlib `csv` strict parser in `spine/core/`** — Spark's CSV parser leaves the trust surface entirely. A record is malformed iff the strict parse raises or the token count ≠ the bound width (§5.3). | Spark CSV **documents** that ragged rows are *not* corrupt records — short rows null-pad, long rows silently drop tokens — so 005 §5.2's tier-2 "ragged row" is undetectable there, and its verdict semantics version with the engine, not the package (the exact complection D-6 rejected DQDL for). Owning the parser makes the verdict a plain-value pure function: property-testable without Spark, byte-identical in CI and Glue (004 D-7), and it retires the whole errata-notes §1.11 class (escape defaults, FAILFAST's U+FFFD blindness). Cost: Python-rate parsing (~10⁵–10⁶ rows/s/core) instead of Univocity — acceptable in a seconds-to-minutes lane; named growth path if a feed outgrows it (§5.9). |
| A-2 | Phase-1 ladder support set | `compression ∈ {none, gzip}` and `charset = utf-8` are implemented; `zstd` and other charsets are **reserved grammar values** — declaring one is a spec-parse defect naming the gap. Declared compression is validated against every object's extension at bind time (tier-1 on mismatch, §5.6). A single leading U+FEFF (BOM) on an object's first line is stripped as part of the declared utf-8 decode. Invalid UTF-8 bytes decode to U+FFFD (replacement), never raise — §6.1's `forbid_replacement_chars` check is the honesty mechanism (005 §5.3). | The exemplar feeds are CSV/UTF-8(/gzip); implementing unused ladder rungs now is speculative capability. Extension-based codec selection is Hadoop's mechanism — declaring compression and *validating* the extension keeps the declaration honest without rebuilding codec dispatch. BOM handling belongs to the framework reader precisely so no upstream driver is ever tempted to "just strip the BOM" (005 §11.2). |
| A-3 | Locator mechanics | `object_seq` = **1-based** position in the lexicographically sorted (codepoint order) `object_uris`; `row_index` = **1-based ordinal of the record within its object as parsed** (skipped lines and the header excluded; empty physical lines yield no record). Determinism: each object is read as a **single split** (§5.1), so partition order cannot reorder lines; `multiline: true` ordinals follow the single-task csv record order (§5.5). Physical line = `skip_leading_lines + header + row_index` under `multiline: false`. | D-9 needs the locator deterministic only for the single guarded write (durability carries reruns), but single-split reading makes it deterministic unconditionally — the subtle Spark split-ordering question (bin-packing does **not** preserve offset order) is dissolved rather than argued about. Cost: no intra-object read parallelism; parallelism is across objects. 1-based indices serve the partner conversation D-9 exists for ("file 1, row 1042"). |
| A-4 | Header binding | Declared column names carry the identifier grammar `^[A-Za-z_][A-Za-z0-9_]*$` and header matching is **exact string equality**. Any exact-duplicate header name (declared or not) is a **tier-1 defect**. Undeclared header columns bind to `extras` under their verbatim names; declared-but-absent non-required columns are all-null. `header: false` binds positionally — token *i* → declared column *i*, the expected width **is** the declared width, and rows longer *or* shorter are malformed (§5.3, one ragged rule for both dialect modes); `extras` is always `{}` for headerless feeds [DC-2] — synthesizing positional extras keys would re-derive a header from data, interpretation creeping into a headerless claim. A `header: false` contract declaring any `required` column is a **spec-parse defect** (the claim is unsatisfiable). Binding is per object; objects union by name onto the fixed raw schema. | Exact match keeps the header a fact, not an interpretation; a partner header that can't be declared (`"Order ID"`) lands visibly in `extras`, and a `source_name` alias field is the named additive growth path — not built ahead of a resident feed needing it. Duplicate names admit no honest binding, and `extras` map keys must be unique. Per-object binding is what makes multi-object deliveries with differing column *order* land correctly. |
| A-5 | Null and typing semantics | An empty token (`""`, quoted or not — the `csv` module cannot distinguish) parses to **SQL NULL**. The typed projection uses **`try_cast`** for numeric/bool types and **`to_date`/`to_timestamp`(fmt)** for temporal types, under a session pinned `spark.sql.ansi.enabled=false`, `spark.sql.legacy.timeParserPolicy=CORRECTED`, `spark.sql.session.timeZone=UTC` — all three set explicitly in the entrypoint session build and the test substrate. The castability check and the cast are the same expression (005 D-5); §6.2's table is the normative semantics, engine-verified. | Plain `cast` **silently truncates** (`'1.239'` → int `1` — verified), which would mutate values inside the remember-to-perceive seam; `try_cast` rejects to null, which the check routes to quarantine. The default `timeParserPolicy` (`EXCEPTION`) **throws** on an unparseable date — one bad cell would kill the batch, violating 001 §2.2 — so `CORRECTED` is load-bearing, not hygiene. Cost: empty-vs-absent conflation for CSV (named; a `null_value` dialect field is additive growth) and the broad SQL bool token set (§6.2, documented). |
| A-6 | Canonical JSON, one implementation | `core/canonical.py` defines the canonical serialization (§7.1): UTF-8, `ensure_ascii=False`, keys sorted bytewise, separators `(",", ":")`, every key always present (nulls explicit), scalar rules per type (§7.1), no unicode normalization. `row_hash` = lowercase hex SHA-256 over the UTF-8 bytes (§7.2). Both quarantine writers use this one function; 007 aligns its fact-hash canonicalization by **shared property-test vectors** (`contracts/fixtures/canonical-json/`), never shared code (005 §13.3, 004 D-13's idiom). | One serializer is what makes D-7's "one shape" a property rather than a convention — the pre/post snapshot structures differ in content, never in serialization rules. Vectors-not-code keeps 007 free to diverge deliberately (fact hashing has different inputs) while making accidental divergence loud. |
| A-7 | Snapshot computation seam | `row_snapshot` and `row_hash` are computed by **one scalar UDF** wrapping `core.canonical` (returns `struct<row_snapshot, row_hash>`), applied only at quarantine **shaping** — violation rows (pre) / violating candidate rows (post); the post_check fresh-path subtraction stays bag-keyed (§8.2 [DC-5]), so the admit path never pays the UDF except on the rare hash-keyed *rerun* path. Timestamp columns are rendered to their canonical strings **in-plan** (`date_format` under the pinned UTC session zone) before the UDF boundary; `canonical_json` **rejects naive datetimes** [DC-3]. Every other pre_check expression — checks, first-failure selection, `reason_detail` — is **native Spark column expressions** (deterministic `to_json` over statically-ordered structs/arrays; no map serialization, §6.4). | The one thing native Spark cannot do deterministically is canonical map serialization (`to_json` of a map does not sort keys); a UDF over the *same* core function every other consumer uses is simpler than a second, almost-canonical native serializer — the exact two-evaluators-that-can-disagree trap D-5/D-6 exist to kill. The in-plan timestamp rendering exists because the Python UDF boundary converts `TimestampType` via the **OS-local zone**, ignoring the session pin (probe-verified) — hashes would otherwise complect value with environment, diverging between CI and Glue. Cost: Python-rate serialization on the violation path only. |
| A-8 | Admission tables partition by `identity(batch_id)` | Raw and quarantine are Iceberg v2 tables partitioned by **`identity(batch_id)`**; no sort order; DDL owned by an idempotent bootstrap (§4.4) that derives raw's columns from the contract, applies **additive-only** evolution (ADD COLUMN), and fails loudly on any other diff. Quarantine's DDL is a pipeline-independent constant (D-7). | Every correctness-path read of these tables is `batch_id`-keyed (guards, `read_batch`, rerun subtraction): identity partitioning makes the guard probe a partition-level miss and **structurally dissolves** the [T-9] compaction-preserves-clustering obligation for admission tables — rewrites cannot cross a partition boundary. Cost: partition count grows linearly with batches (one per delivery); at delivery cadence this is thousands/year — 008 reviews the cardinality with real data (§15.2). |
| A-9 | pre_check rerun: durable rows authoritative — **both doors** | On a guard-skipped rerun, `valid_df` = durable raw rows **minus the durable quarantine locators** for `(batch_id, "pre_check")` (anti-join on the full locator), then minus flagged rows (`malformed_text IS NOT NULL` — by construction, both paths), then the typed projection under the *current* contract. The recomputed predicate runs as a **probe**: locator-set symmetric difference and admitted-row cast failures are folded into a new `BatchContext.pre_check_drift: str \| None`, recorded via the exact `post_check_drift` machinery (ledger `error_message` on non-failed rows + WARNING + EMF `PreCheckDrift`) — never raised. **The second door [DC-1]:** a zero-violation batch writes no quarantine row, so its guard stays absent forever — a deliberate `--rN` rerun after a contract change would re-evaluate fresh and append quarantine rows for rows already committed as facts, silently breaking complementarity. So the fresh path first probes `table_has_batch(fact_table, batch_id)`: **facts present ⇒ durable state authoritative** — empty violation set, no append, recompute demoted to the same drift probe. The §6.1 count identity is asserted only on the genuinely-fresh path (both probes absent). | This is 005 §7.2 made mechanical, and it is a **behavioral change**: today's `pre_check` recomputes on guard-skip (`stages/pre_check.py:71-77`). Locator-keyed subtraction is available *now* — unlike post_check's — because every pre_check quarantine row carries a non-null unique locator (D-9). The fact-table probe's cost rests on the *fact* table's `batch_id` pruning — 004.1 I-3's stats/clustering argument and the [T-9] obligation 008 carries for fact tables, **not** A-8 (which governs only the admission tables) [R2-3]; commit's guard already probes the same table with the same predicate every run, so this is a second instance of an already-paid read. Proposed as a 005 §7.2/§10 erratum (§15.3), and applied symmetrically at post_check [R2-1] (§8.2). Reusing the drift channel errata-notes §1.5–1.6 built means zero new ledger columns. |
| A-10 | Tier-1 defect surface | Tier-1 failures raise **plain `ValueError`** (the errata-notes §1.4 class — deterministic, burns SFN retries loudly) with the pinned message grammar `admission-defect/<code>: <machine detail>`; codes: `undecodable-object`, `required-column-missing`, `duplicate-header-column`, `compression-extension-mismatch`, `reserved-ladder-value`. Messages reference objects by **`object_seq`** and columns by name — never URIs or filenames ([S-8]: partner filenames are payload; the ledger and logs are lower-classified). The header probe (§5.2) reads each object's opening lines before any append, so corruption at the head of a stream surfaces as a named defect; corruption deeper in the stream surfaces during the append action as the raw engine error — deterministic and loud, but unnamed (accepted residual, §9). | One exception class was already law (§7.0); what tier-1 needed was a message grammar, not a type. The no-URI rule closes a classification leak that would otherwise ride `error_message` into an append-only, Athena-queried table. |
| A-11 | Versions are content hashes of parsed values | `read_spec_version` = SHA-256 (lowercase hex, full) of the canonical JSON of the **parsed** `ReadSpecModel`; `check_version` = SHA-256 of the canonical JSON of the parsed pair `{"raw_contract": …, "read_spec": …}`. Computed once at binding, carried on the context, stamped per row (raw: `read_spec_version`; quarantine: `check_version`). | 005 §13.1 requires versions over the canonical parsed form so 009's re-homing of the authored file cannot silently change version identity. The pair-hash for `check_version` answers "which declared admission surface rejected this row" without a per-reason sourcing rule — D-2 already binds the two surfaces into one reviewed unit, so their versions may honestly fuse. Parquet dictionary-encodes a per-batch-constant column to nothing; full hex costs no real storage. |
| A-12 | Spec model migration | `PipelineSpecModel` drops `required_columns` and `read` (both marked "005 replaces/owns") and gains `read: ReadSpecModel` and `raw_contract: RawContractModel` — required fields, `extra="forbid"` unchanged. The exemplar `pipeline.yaml`, its violations variant, every test spec, and the deployed dev spec migrate in-phase; `tools/export_schemas.py` regenerates `pipeline-spec.v1.json` (drift-gated). | The spec is the runner-consumed value, explicitly not 009's frozen authored surface (004.1 §6.2); a hard cut now is cheaper than a deprecation window for two fields with exactly one consumer (the exemplar). Reusing the key `read` keeps 005 §5.1's authored shape recognizable. |
| A-13 | The U+FFFD scan, defined | The `forbid_replacement_chars` check (default on) fails a row iff **any declared column value, any `extras` value *or key* [DC-9], or `malformed_text`** contains U+FFFD — an expression over durable raw columns, recomputable on any attempt (the E-5 requirement), no flag column needed. It **does** apply to `malformed_text` (005 §13.3's open question): on a malformed row the encoding finding rides `reason_detail`'s failed-set while `unreadable/malformed-row` stays the primary reason (§6.4's evaluation order). | Scanning durable columns rather than the pre-parse line keeps the check a function of (durable raw, contract@v) — nothing an attempt cannot re-derive. Declared delimiters/quotes are ASCII, so cells ∪ `extras` keys ∪ `malformed_text` covers everything a decoded line can carry — the keys matter because a mojibake *header's* undeclared tokens land as `extras` keys, not values [DC-9]. |
| A-14 | Quarantine one-shape forces two post_check changes now | (a) The `violations_df` contract's `reason` column **must fullmatch `^business/[a-z0-9][a-z0-9-]*$`**; a nonconforming reason is a named defect (plain `ValueError`, fail-fast) — free text cannot be verified value-free, and [S-9] is law. (b) The **fresh path keeps the existing bag subtraction** (`frames/checks.py::violation_subtraction` — both sets are candidate-shaped in memory, nothing forces a change there [DC-5]); the **guard-skip rerun** subtraction becomes **`row_hash`-keyed**: recompute the candidate rows' canonical hashes, anti-join the durable `row_hash` set for `(batch_id, "post_check")` — the all-column anti-join is impossible on *that* path once durable quarantine rows carry `row_snapshot` instead of candidate columns. Two subtraction mechanisms instead of one is the honest cost of keeping the fresh path's multiplicity semantics and UDF-free plan intact; each path pays only what it must. Within one attempt, a deterministic row-wise check gives identical verdicts to value-identical rows, so hash subtraction preserves I-12's multiplicity semantics for every conforming check; the occurrence-relative counterexample is exactly the precondition 006 must rule on. Fresh-path count identity and [H-2]'s rerun demotion are unchanged. |

## 3. Contracts and Data Model

All boundary models are pydantic v2 in `spine/core/model.py`, `extra="forbid"`, exported to JSON Schema by `tools/export_schemas.py` and drift-gated (`make -C spine schemas`). Internal values are frozen dataclasses. Parse, don't validate — with narrow types (004.1 §6 systemic rule).

### 3.1 `ReadSpecModel` (the spec key stays `read:` — 005 §5.1's shape)

```python
class DialectModel(BaseModel):
    model_config = ConfigDict(extra="forbid")
    format: Literal["csv"]                     # fixed-width/jsonl/ebcdic: reserved (005 §5.5)
    delimiter: str = ","                       # exactly 1 char, ASCII printable, != quote
    quote: str = '"'                           # exactly 1 char, ASCII printable
    header: bool = True
    multiline: bool = False                    # true = declared §5.4 trade-off; §5.5 path

class ReadSpecModel(BaseModel):
    model_config = ConfigDict(extra="forbid")
    compression: Literal["none", "gzip", "zstd"] = "none"   # zstd reserved (A-2)
    charset: Literal["utf-8"] = "utf-8"        # other charsets: reserved values (A-2)
    dialect: DialectModel
    skip_leading_lines: int = Field(default=0, ge=0, le=4096)
```

Validators: `delimiter != quote`; both single ASCII printable chars; `compression == "zstd"` raises at parse with the reserved-value message (A-10's `reserved-ladder-value` grammar — a spec defect, pre-land). Escaping is RFC-4180 quote doubling only (the `csv` module's native semantics); an `escape_char` field is named growth, not built.

### 3.2 `RawContractModel` and the column grammar (005 §7.1, hardened)

```python
COLUMN_NAME_RE = r"^[A-Za-z_][A-Za-z0-9_]*$"           # fullmatch; also the Iceberg-safe set
COLUMN_TYPE_RE = (
    r"^(string|int|long|bool"
    r"|decimal\([1-9][0-9]?,(0|[1-9][0-9]?)\)"
    r"|date\([^()]+\)|timestamp\([^()]+\))$"
)

class ColumnSpec(BaseModel):
    model_config = ConfigDict(extra="forbid")
    name: str = Field(pattern=COLUMN_NAME_RE, max_length=128)
    type: str = Field(default="string", pattern=COLUMN_TYPE_RE)
    required: bool = False                     # header claim — tier 1 (005 §7.1)
    nullable: bool = True                      # cell claim — tier 3
    allowed_values: list[str] | None = None    # compared on the raw string (§6.1)
    pattern: str | None = None                 # fullmatch on the raw string (§6.1)
    min: str | None = None                     # bound in the column's own type, as a string
    max: str | None = None                     #   literal; cast at compile time (§6.1)

class RawContractModel(BaseModel):
    model_config = ConfigDict(extra="forbid")
    columns: list[ColumnSpec] = Field(min_length=1, max_length=1024)
    forbid_replacement_chars: bool = True      # 005 §5.3; opt-out is a reviewed contract edit
```

Model validators, all spec-parse-time (fail pre-land, binding-defect class): column names unique **and disjoint from the framework raw columns** (`batch_id`, `delivery_id`, `feed_id`, `received_at`, `source_uri`, `object_seq`, `row_index`, `read_spec_version`, `malformed_text`, `extras`) **and from the reserved prefix `_conveyer_`** [DC-6] — a colliding name would otherwise produce duplicate-column DDL at bootstrap and a key collision in §7.1's snapshot object, breaking `row_hash` injectivity; `decimal` precision ≥ scale **and ≤ 38** (Spark's ceiling — beyond it the failure would be an unnamed engine error at compile instead of a named spec defect [DC-10]); `date`/`timestamp` fmt non-empty and drawn from the Spark datetime pattern alphabet (pure string check; full validity re-fails at bind, §6.1); `min`/`max` only on `int|long|decimal|date|timestamp` columns, authored **in the column's own declared format** — plain numeric literals for `int|long|decimal`, the column's `fmt` for temporals — and parseable as the column's type (checked at compile) [R2-5b]; `pattern`'s **normative grammar is Java regex** (the executing engine) — spec parse runs a best-effort `re.compile` typo check only, and bind-time validation compiles the pattern through the JVM (`java.util.regex.Pattern.compile` via the driver session, pre-land, binding-defect class) so the two engines cannot silently disagree [DC-4]; applied with **fullmatch anchoring `\A(?:…)\z`** — lowercase `\z`: Java's `\Z` permits a final line terminator, which would resurrect the exact trailing-newline bug class this repo already fixed once (probe-verified: `rlike '\A(?:foo)\Z'` matches `"foo\n"`); `allowed_values` non-empty when present, each ≤ 1024 chars; `min <= max` when both present. Two cross-model rules, checked at `PipelineSpecModel` parse (both surfaces in hand): a contract where `dialect.header is False` and any column has `required: True` is rejected (A-4 — unsatisfiable claim); and under `dialect.header is True`, **`nullable: False` requires `required: True`** [R2-2] — demanding non-null cells from a column whose header presence you don't demand is incoherent, and its failure mode is a trap: the column absent from a header binds all-null (A-4), turning a header-level condition into 100 % tier-3 quarantine instead of a tier-1 defect. (Under `header: False` the rule is vacuous — positional binding always provides the column; short rows are malformed, not null-padded.) `core/contract.py::parse_column_type(s) -> ColumnType` (frozen dataclass: `kind` + params) is the **single interpreter** of the type grammar, used by the frames compiler (§6.1) and nothing else — raw DDL never sees types (D-5: raw columns are strings, so a type change is not a DDL event).

## 4. Tables — DDL, Partitioning, Bootstrap

### 4.3 Partitioning rationale and the [T-9] dissolution (A-8)

Guard probes (`table_has_batch`), `read_batch`, and the rerun subtractions are all `batch_id`-equality reads; `identity(batch_id)` makes each a single-partition plan, and a probe for an absent batch a metadata-only miss. Compaction (008) rewrites within partitions by construction, so the "preserve `batch_id` clustering" obligation 004.1 [T-9] registers for fact tables is **discharged structurally** for admission tables — recorded for 008's register (§15.2) together with the counter-obligation: review partition cardinality when real feed cadence exists (one partition per batch; small-file pressure inside a partition is bounded by the one-commit invariant — each batch's files arrive in exactly one append).

### 4.4 Bootstrap — `spine/bootstrap/create_admission_tables.py`

Idempotent, mirrors `create_run_ledger.py`'s shape; driver-side Spark SQL DDL against the target catalog:

```
create_admission_tables.py --spec-uri <pipeline spec> [--catalog spine_cat] [--env …]
```

1. Parse the spec (same `PipelineSpecModel` path as the entrypoint — one parser).
2. Raw: if absent, `CREATE TABLE` per §4.1 (declared columns from `raw_contract`). If present, diff actual vs expected columns — **name-and-type-keyed, order-insensitive** [DC-11] (an order-sensitive diff would fail forever after the first promotion, since `ADD COLUMN` appends after `extras`): **missing declared columns → `ALTER TABLE … ADD COLUMN` (string)**; any other diff — type mismatch, framework-column mismatch, column present in the table but neither framework nor declared nor `extras` — is a **loud failure** naming the diff. Never drops, never retypes, never reorders (additive-only, 001 §7, enforced here rather than reviewed-for).
3. Quarantine: if absent, `CREATE TABLE` from the constant DDL; if present, assert exact schema equality (the shape is versionless by design — a diff means a framework upgrade forgot its own migration note; fail loudly).
4. Contract-column **promotion from `extras`** (D-11) is *only* step 2's ADD COLUMN — new rows land natively, history stays in `extras`, and the coalescing view is authored at promotion time by the operator (an Athena view, named in the runbook; not machinery here).

Run by the deploy principal (runbook §11.3), never by the job role. Test parity: `tests/integration/scenario_helpers.py` **deletes its hand-rolled `ROW_DDL`** and calls the bootstrap module's DDL builders — one authored schema, both substrates (the D-7 discipline applied to DDL).

### 4.5 Grants and classification (005 §8.4 — no new IAM objects)

The per-pipeline job role's existing grants (004.1 I-21: S3 `Get/Put/List` on `${p}-lake/tables/<slug>/*`, per-table Glue catalog on `<slug>__*`) already cover both tables; bootstrap runs as the deploy principal. The remediation role and queue views are 012's; the standing rule they inherit is restated once: `row_snapshot`, `source_uri`, `extras`, and `malformed_text` carry raw's data classification — a queue view projects reason/lineage columns only.

## 5. The Reader — `land`'s acquisition pipeline

### 5.1 Per-object pipeline (A-1, A-3)

`fx.read_objects` (rewritten, §5.8) processes `sorted(object_uris)` (codepoint order), assigning `object_seq` 1…N, and unions the per-object frames onto the fixed raw-row schema. Per object, `multiline: false` path:

1. **Acquire lines, single-split**: `sc.newAPIHadoopFile(uri, TextInputFormat, LongWritable, Text, conf={"mapreduce.input.fileinputformat.split.minsize": str(2**63 - 1)})` — one split ⇒ one partition ⇒ line order is file order, unconditionally (A-3). Gzip decompresses via the extension-selected codec (validated, §5.6); text decodes UTF-8-with-replacement (Hadoop `Text` semantics — the §5.3/A-13 posture). Values only; offsets discarded.
2. **Enumerate** within the single partition (`mapPartitions` + `enumerate` — no shuffle, no extra job): physical line ordinal 0….
3. **BOM strip**: remove one leading U+FEFF from line 0 (A-2).
4. **Skip** `skip_leading_lines` lines.
5. **Header** (when `dialect.header`): the next line is the header — parsed driver-side by the same `core` parser (§5.2's probe collects only this line), bound per §5.2/A-4. Data records start after it.
6. **Parse each remaining line independently** with `core/reading.py::parse_line` (§5.3); assign `row_index` = 1-based data-record ordinal (empty lines yield no record and no ordinal).
7. **Shape** each parsed record per the header binding: declared cells (empty token → NULL, A-5), undeclared → `extras`, malformed → `malformed_text` with declared cells NULL and `extras = {}`.
8. Emit rows `(source_uri, object_seq, row_index, malformed_text, <declared…>, extras)`; `toDF` against the explicit raw-row schema (minus lineage/stamp columns, added by `frames.stamp_raw_lineage`).

The decode ladder runs at read time only; nothing intermediate is written (005 §5.1). Steps 2–8 execute inside one `mapPartitions` closure in `effects/spark.py` whose per-record logic is entirely `core/` pure functions — the effects layer contributes acquisition and the DataFrame boundary, nothing semantic.

### 5.2 Header probe and binding (A-4, A-10)

Before any append, `read_objects` probes every object: a `limit`-bounded read of the first `skip_leading_lines + 1` lines (cheap even for gzip — the stream stops early). Failures here are tier-1 defects raised pre-append:

- object stream unreadable at the head (corrupt gzip, zero lines where a header is required) → `admission-defect/undecodable-object: object_seq=<n>`;
- header parse yields exact-duplicate names → `admission-defect/duplicate-header-column: object_seq=<n> positions=[<i>,<j>]` — duplicates are reported by **position**; the token itself is named only when it exactly equals a *declared* (contract-authored) column name, because an arbitrary header token is a partner-authored string, and the sharpest case — a mis-uploaded file whose first line is data — would put a cell value into the ledger's `error_message` [DC-8];
- any `required` column absent → `admission-defect/required-column-missing: object_seq=<n> columns=[…]` — for the **whole batch** (005 §7.1: no partial admission).

`core/reading.py::bind_header(tokens, contract, dialect) -> HeaderBinding` is pure: maps each header position to a declared column, an `extras` key, or (header:false) positional targets; records the expected token width. The probe runs only on the fresh path — a guard-skipped land never re-reads objects.

### 5.3 The line parser — `core/reading.py::parse_line`

```python
@dataclass(frozen=True)
class ParsedLine:
    tokens: tuple[str, ...] | None             # None ⟺ malformed
    error: str | None                          # csv strict error text; never persisted

def parse_line(line: str, dialect: DialectValue) -> ParsedLine: ...
```

`csv.reader([line], delimiter=…, quotechar=…, doublequote=True, escapechar=None, strict=True)` — **one reader per line, deliberately**: feeding a shared reader the whole line stream would let an unterminated quote swallow subsequent lines, which is exactly the `multiline: false` contract's forbidden behavior. Verdicts (engine-verified §12.4):

- strict parse raises `csv.Error` (unterminated quote: *unexpected end of data*; junk after a closing quote: *"',' expected after '\"'"*) → malformed;
- token count ≠ the binding's expected width (ragged, short or long) → malformed (applied by the caller, which owns the width);
- empty line → no record (skipped, §5.1.6);
- NUL and other control characters are **values, not structural errors** (Python 3.11 `csv` accepts NUL — verified); hygiene beyond structure is contract-grammar territory (`pattern`), registered against `conveyer-nvh.48.14` (§15.2).

`parse_line` needs `try` (converting `csv.Error` into a value — defects-as-values); `core`'s linter profile gets a `_TRY_RAISE_ALLOWLIST` entry for it (§12.6).

### 5.4 Malformed-row capture (D-4, mechanical)

A malformed record becomes a raw row, never an error: `malformed_text` = the decoded line verbatim (unparsed — 005 §6.1's "undecoded" read as *undialected*; it is necessarily post-charset-decode, a one-line clarification proposed to 005, §15.3), declared columns NULL, `extras = {}`. It counts in `raw_count`, rides the one land append, and is quarantined by pre_check as `unreadable/malformed-row` (§6). FAILFAST is gone; no read-time failure mode remains at row granularity.

### 5.5 `multiline: true` path (005 §5.4's declared trade)

`spark.read.text(uri, wholetext=True)` (one row per object) → one task parses the whole decoded content: BOM strip, drop `skip_leading_lines` physical lines, then `csv.reader(content_lines_keepends)` over the remainder — embedded newlines inside quotes now parse, `row_index` = 1-based csv record ordinal, and an unterminated quote consumes the file's remainder into one field (the named §5.4 cost, observable in A-13's test). Costs, named: whole-object memory and the JVM 2 GiB string ceiling — an object beyond it fails the job loudly; the reviewed read-spec PR carries the risk (005 §5.4).

### 5.6 Compression and charset validation (A-2)

At bind time (pre-probe): `compression: gzip` requires every `object_uri` to end `.gz`/`.gzip`; `none` requires none of the compression extensions Hadoop would act on (`.gz .gzip .zst .bz2 .lz4 .snappy .deflate`) — mismatch is `admission-defect/compression-extension-mismatch: object_seq=<n>` (tier-1). This keeps the declaration honest while the codec dispatch itself stays Hadoop's extension mechanism. Charset is `utf-8` (A-2): decode-with-replacement plus the §6.1 U+FFFD check; a total-mojibake stream (wrong declared charset, truncated multibyte prefix) fails the header's required-column check — tier-1 by subsumption, proposed as a 005 §5.2 clarifying erratum (§15.3).

### 5.7 Defect table (tier-1 surface, complete)

| Code | Raised | When |
|---|---|---|
| `reserved-ladder-value` | spec parse (pre-land, binding class) | `zstd`, non-utf-8 charset, non-csv format declared |
| `compression-extension-mismatch` | bind, pre-probe | §5.6 |
| `undecodable-object` | header probe | stream unreadable at head; header line absent |
| `duplicate-header-column` | header probe | exact-duplicate header names |
| `required-column-missing` | header probe | any object's header missing a `required` column |

All plain `ValueError`, message grammar per A-10, no URIs/filenames in messages. Late-stream corruption (§9) and pathological single-line objects (memory) remain **unnamed loud failures** — deterministic, ledger-visible via the failed land row, accepted residuals.

### 5.8 `fx.read_objects` — signature change (004.1 erratum, §15.3)

```python
read_objects: Callable[[tuple[str, ...], ReadSpecModel, RawContractModel], DataFrame]
```

Returns the shaped, locator-stamped frame of §5.1.8. The provisional `Mapping[str, JsonValue]` hints parameter dies with I-P1. Same erratum class as errata-notes §1.1 (implementation-forced signature hardening).

### 5.9 `land.py` deltas

Unchanged in shape (guard → read → stamp → one append → read-back → emit). Deltas: fresh path calls the new `read_objects(ctx.object_uris, spec.read, spec.raw_contract)`; `frames.stamp_raw_lineage` gains a `read_spec_version: str` parameter (raw-only lineage divergence — the seam `frames/lineage.py` documents for 005); `raw_count` (append summary `added-records`) now **includes flagged rows** — the number `batch-started` carries (005 §6.1), noted for 008's payload freeze (§15.2). Growth path if Python-rate parsing ever binds a real feed's SLA: a JVM-native fast path must reproduce §5.3's verdicts against the A-suite vectors before it may ship — recorded so the option exists without licensing a second semantics.

## 6. `pre_check` — Compilation and Evaluation

### 6.1 Compiled checks (`frames/checks.py`, rewritten)

`compile_contract(contract: RawContractModel) -> CompiledContract` — a frozen dataclass of check entries in **normative evaluation order**: the 005 §7.1 table's row order major, contract column order minor:

| # | Check (id) | Applies | Expression (semantics) | Reason code |
|---|---|---|---|---|
| 1 | `malformed-row` | row | `malformed_text IS NOT NULL` | `unreadable/malformed-row` |
| 2 | `encoding-suspect` | row (unless opted out) | A-13: any declared col, any `extras` value **or key** (`exists(map_values(…))` ∨ `exists(map_keys(…))` [DC-9]), or `malformed_text` `contains` U+FFFD | `unreadable/encoding-suspect` |
| 3 | `cast:<type>` | per non-string column | `col IS NOT NULL AND <typed-expr>(col) IS NULL` (§6.2) | `contract/cast-failure` |
| 4 | `not-nullable` | per `nullable: false` column | `col IS NULL` | `contract/null-violation` |
| 5 | `allowed-values` | per column with `allowed_values` | `col IS NOT NULL AND NOT col IN (<literals>)` — raw string comparison | `contract/value-not-allowed` |
| 6 | `pattern` | per column with `pattern` | `col IS NOT NULL AND NOT rlike(col, '\A(?:…)\z')` — fullmatch anchoring, lowercase `\z` (Java-regex-normative, JVM-validated at bind — §3.2 [DC-4]) | `contract/pattern-mismatch` |
| 7 | `bounds` | per column with `min`/`max` | `<typed-expr>(col)` outside the compile-time-cast literals; NULL-safe (a failed cast is check 3's finding, not a bounds finding) | `contract/out-of-bounds` |

Checks 3–7 skip NULL cells except check 4 (null-handling is exactly one check's job — no double-counting). The `required` header check is **not here** — it ran at land (005 §7.1: the contract is a land-time input). Checks are pure column expressions over durable raw columns + the versioned contract — nothing else (co-effect-freedom by construction, E-5). The compiler validates date/timestamp fmts by constructing the expressions (a malformed fmt fails at bind, pre-land).

### 6.2 Cast semantics — normative, engine-verified

The castability check and the cast are one expression per type (D-5). PySpark 3.5's `Column` API lacks `try_cast` (it arrives in 4.0), so numeric/bool typed-exprs are built with `F.expr("try_cast(`<name>` AS <type>)")` — expr text composed **only** from the grammar-validated column name (backticks doubled, `merge.py`'s quoting rule) and the compiler's own rendering of the parsed `ColumnType`, never authored text. The linter's string-SQL sink list gains `expr`, with `frames/checks.py::_typed_expr` as a named `(file, function)` exemption — the §6.7-merge-render precedent (§12.6).

| Declared type | Expression | Verified semantics (Spark 3.5, ANSI off, CORRECTED, UTC) |
|---|---|---|
| `string` | identity | never fails |
| `int` / `long` | `try_cast(c AS int/long)` | trims whitespace (`" 42 "` → 42); leading zeros ok; **fractions rejected** (`"1.5"` → NULL — plain `cast` would truncate to `1`; that is why `try_cast` is normative); overflow → NULL; **scientific notation rejected** (`"1e2"`/`"1.5e2"` → NULL, plain and whitespace-trimmed — asymmetric to `decimal` below, A-15-pinned) |
| `decimal(p,s)` | `try_cast(c AS decimal(p,s))` | precision overflow → NULL; **excess scale rounds** (`"1.239"` → `1.24` — SQL cast semantics; exact rounding mode pinned by A-15's executable table, which includes the half-even discriminator `"1.245"`); the raw string survives in raw forever, so rounding is a declared projection semantics, not information loss; **scientific notation accepted** (`"1.5e2"`/`" 1.5e2 "` → `150.00` — documented engine behavior, A-15-pinned; not a decision, `int`/`long` above reject the identical tokens) |
| `bool` | `try_cast(c AS boolean)` | accepts (case-insensitive) `true/false/t/f/y/n/yes/no/0/1` — the SQL set, broader than `true/false`; documented; a feed wanting strict booleans declares `allowed_values` or `pattern` |
| `date(fmt)` | `to_date(c, fmt)` | strict, non-lenient under CORRECTED: `"2024-02-30"` → NULL, `"2024-2-3"` (unpadded vs `yyyy-MM-dd`) → NULL. **The session pins are load-bearing**: the default `timeParserPolicy=EXCEPTION` *throws* on unparseable input — one bad cell kills the batch (verified) — and Spark 4 flips the ANSI default; both configs are set explicitly in `glue_main`'s session build and `tests/conftest.py` |
| `timestamp(fmt)` | `to_timestamp(c, fmt)` | as `date(fmt)`; naive inputs interpret in the pinned UTC session zone — a feed carrying zoned timestamps declares the zone in `fmt` |

`valid_df` = rows with no failed check and `malformed_text IS NULL`, projected to **declared columns only** (extras, flags, locators, lineage all excluded — 005 §6.1's strict projection; `apply` cannot grow a dependency on undeclared content), each column cast by the same typed-expr. A row admitted is a row that cast; there is no second cast to disagree (005 §7.2).

### 6.3 One evaluation, two outputs

`evaluate(raw_df, compiled)` adds one internal column `_conveyer_admission_failures` — `filter(array(<struct(code, column, expected) per check, evaluation order>), x -> x.failed)` — from which both outputs derive: `valid_df` (empty failures) and `violations_df` (non-empty). One compiled predicate, two projections; the fresh-path count identity `raw_count == |valid_df| + pre_quarantined_count` is asserted after the append (from the append summary + one count job — post_check's existing assert idiom), fresh path only ([H-2] mirror). The internal column is dropped from both outputs before they leave `frames/`.

### 6.4 Reason shaping (005 §8.1's grain)

Per violation row: `reason_code` = first entry of the failures array (evaluation order is the declared order — 005 §8.1); `reason_detail` = `to_json` of the full failures array — deterministic natively, because the array is statically ordered and struct fields (`code`, `column`, `expected`) are compile-time-fixed (no map, no sorting problem; A-7). `expected` is a class string (`"decimal(5,2)"`, `"record(width=7)"`, `"pattern"`, `"non-null"`) — never a cell value, never a URI ([S-9]/D-8). Detail arrays are truncated at 32 entries with a final `{"truncated": <n_total>}` element (bounded machine context).

### 6.5 Guard-skip: read-back subtraction + drift probe (A-9)

Three paths, decided by two probes — the quarantine guard `(batch_id, "pre_check")` and the fact-table presence probe `table_has_batch(fact_table, batch_id)` [DC-1]:

**Genuinely fresh** (both absent): §6.3, guarded append keyed `(batch_id, "pre_check")`, zero violations ⇒ no write (naturally idempotent, unchanged); count identity asserted here and only here.

**Facts present, quarantine guard absent** [DC-1] — the zero-violation batch rerun (deliberate `--rN` after a contract change is the live case): durable state is authoritative. The batch's committed facts embody an empty pre_check violation set; recomputing under the current contract and appending would quarantine rows already committed as facts — a silent complementarity break through the one door the quarantine guard cannot see (zero violations wrote no guard row). So: **no append**, `valid_df` = raw minus flagged rows, typed projection under the current contract, and the recompute demotes to the same drift probe as below. No count-identity assertion ([H-2]'s logic — the identity can fail deterministically here and wedge a batch whose only remaining job is to re-announce). The minus-flagged filter on this door is provably vacuous — a flagged row would have quarantined, written the guard, and forced door 1, so door 2 implies zero flagged rows — kept as defense-in-depth, with the invariant stated so the door-2 argument stays sharp [R2-5c]. Proposed as a 005 §7.2/§10 erratum (§15.3).

**Quarantine guard present** (the A-9 subtraction path):

1. `durable_q` = `read_batch(quarantine, batch_id)` filtered `check_stage = 'pre_check'`, projected to the locator triple.
2. `valid_df` = `raw_df` filter `malformed_text IS NULL`, **anti-joined** to `durable_q` on `(source_uri, object_seq, row_index)` — durable rows authoritative — then typed-projected under the current contract (§6.2). Rows whose non-string cells fail the *current* cast stay in `valid_df` with NULL cells: recorded, never dropped (005 §7.2's letter).
3. **Probe**: recompute §6.3's violation locator set; `pre_check_drift` = `None` when it equals the durable set and no admitted-row cast failures exist, else a value-free summary string: `"pre_check drift: durable=<d> recomputed=<r> only_durable=<a> only_recomputed=<b> admitted_cast_failures=<c> check_version=<hash[:16]>"`. Recorded as data (ledger `error_message` on the non-failed row, WARNING, EMF `PreCheckDrift`) — never raised. No count-identity assertion on this path.
4. `pre_quarantined_count = 0` (attempt delta — the ledger's healthy-rerun signature); snapshot id via stamped-summary resolution, unchanged.

`frames/checks.py::locator_subtraction(raw_df, durable_locators)` is the pure plan half; the stage composes. `violation_subtraction` (the post_check bag-subtract) is superseded by §8.2's hash subtraction — one deletion, not two mechanisms.

### 6.6 `pre_check.py` flow (normative summary)

```
raw_df    = ctx.raw_df                     # durable read-back (land ③) — E-5's ground
compiled  = checks.compile_contract(spec.raw_contract)
q_present = fx.table_has_batch(quarantine, batch_id, "pre_check")
f_present = fx.table_has_batch(spec.fact_table, batch_id, None)          # [DC-1]
pre_quarantined_count = 0                  # explicit before any branch [DC-13][R2-5a]
if q_present:                              # rerun door 1: durable quarantine authoritative (A-9)
    valid_df, drift = §6.5 locator subtraction + probe
elif f_present:                            # rerun door 2: committed facts ⇒ empty violation set [DC-1]
    valid_df = typed_projection(raw_df minus flagged, compiled); drift = probe only
else:                                      # genuinely fresh: one evaluation, two outputs
    evaluated = checks.evaluate(raw_df, compiled)
    valid_df  = checks.typed_projection(evaluated, compiled)
    viol      = checks.violations(evaluated, compiled)
    if viol nonempty:
        shaped = quarantine.shape_pre_quarantine(viol, stamp, ctx.check_version, fx.now())
        pre_quarantined_count, _ = fx.append(quarantine, shaped, batch_id, "pre_check")
    assert raw_count == valid_count + pre_quarantined_count     # genuinely-fresh path only
```

## 7. Canonical JSON, `row_snapshot`, `row_hash`

### 7.1 Serialization — `core/canonical.py::canonical_json(value) -> str`

Total and injective over the value domain below; property-tested (§12.4):

- **Objects**: keys sorted by UTF-8 byte order; every schema key always present (explicit `null`); separators `(",", ":")`; no insignificant whitespace.
- **Strings**: verbatim — `ensure_ascii=False`, minimal JSON escaping, **no unicode normalization** (the verbatim claim outranks prettiness).
- **Numbers**: `int` as JSON integers; `Decimal` as **strings** (exact, scale-preserving — no float round-trip); floats are rejected (no admission value is a float; a future producer passing one is a defect, not a coercion).
- **Temporal**: `date` → `"YYYY-MM-DD"`; `timestamp` → RFC 3339 UTC with exactly six fractional digits (`"2026-01-02T03:04:05.000000Z"`) — fixed width kills trailing-zero ambiguity. **Naive `datetime` inputs are rejected** (the float-rejection idiom): the UDF boundary is where naiveté would smuggle in an environment dependency [DC-3], so the serializer refuses rather than guesses.
- **Bool/None**: `true`/`false`/`null`. **Maps**: objects under the same key ordering. **Sequences**: arrays, order preserved.

**pre_check snapshot structure** (both `unreadable/…` shapes, one total schema — 005 §13.3 discharged): `{"<declared col>": str|null …, "extras": {…}, "malformed_text": str|null}` — declared keys always present, `extras` always an object. Malformed rows: declared all null, `extras` `{}`, `malformed_text` the line. Locators and lineage are **not** in the snapshot (they are typed quarantine columns; duplicating them would complect attribution with value-identity and break D-7's value-determined `row_hash`).

**post_check snapshot structure**: the candidate row's columns (typed values under the scalar rules above), sorted keys, all keys present.

### 7.2 `row_hash`

`sha256(canonical_json(snapshot).encode("utf-8")).hexdigest()` — 64 lowercase hex chars. Value-identity, not occurrence-identity (005 §8.1's stated semantics — two identical offending rows collide by design).

### 7.3 The UDF seam (A-7)

`frames/quarantine.py` registers one scalar UDF over `core.canonical`: input the snapshot struct (pre: declared cols + `extras` + `malformed_text`; post: the candidate struct), output `struct<row_snapshot string, row_hash string>`. **The timestamp hazard, closed [DC-3]:** the Python UDF boundary converts `TimestampType` values via the *OS-local* zone (`fromInternal` → `fromtimestamp`), silently ignoring the session's UTC pin — probe-verified: with OS TZ `America/New_York`, `2026-01-02 03:04:05` arrives as naive `datetime(2026, 1, 1, 22, 4, 5)`. Hashes computed over that would complect **value with environment** — CI goldens diverging from Glue, and §8.2's hash-keyed rerun coherent only by TZ luck. So timestamp columns are rendered to their canonical strings **in-plan** (`date_format(col, "yyyy-MM-dd'T'HH:mm:ss.SSSSSS'Z'")` — a SQL expression, which *does* honor the session zone) before the struct reaches the UDF; `Decimal` and `date` cross the boundary typed (both environment-independent); `canonical_json` rejects any naive `datetime` outright (§7.1). A property test ties the plan-side rendering to `canonical_json`'s own rendering of the same instant (§12.4), and the vectors carry a timestamp case. Applied to violation rows only at shaping — plus §8.2's rerun-path candidate hashing, the one admit-path exception.

### 7.4 Shared vectors for 007

`contracts/fixtures/canonical-json/*.json`: `[{ "value": <json-encodable input>, "canonical": "<exact string>", "sha256": "<hex>" }]` — covering key sorting, unicode (incl. U+FFFD and astral plane), decimal scale, temporal fixed-width, empty/nested maps, the two pre_check structures. Spine tests assert `canonical_json` reproduces every vector; 007's fact-hash suite consumes the same files (004 D-13's fixture idiom — shared vectors, no shared code).

### 8.2 post_check deltas (interim — 006-registered, A-14)

1. **Reason grammar at the seam**: `viol.reason` must fullmatch `^business/[a-z0-9][a-z0-9-]*$`; violation is a named defect (fail fast, deterministic — the pipeline author fixes their `post_check`). Free text cannot be mechanically verified value-free; [S-9] wins. The exemplar's violations variant migrates to `business/negative-amount`.
2. **Path selection mirrors §6.6 exactly — the [DC-1] door exists here too [R2-1].** A zero-violation post_check writes no `(batch_id, "post_check")` guard row, so a deliberate `--rN` after commit re-enters the *fresh* path with recomputed candidates under current business rules and current co-effects — and would append quarantine rows for candidates already committed as facts, the same silent complementarity break one stage later. So post_check decides by the same two probes: quarantine guard present → path 4; else **facts present → durable state authoritative**: empty violation set, `admitted = candidate`, **no append**, recompute demoted to the existing `post_check_drift` probe ([H-2]'s channel; no count-identity assertion); else genuinely fresh → path 3.
3. **Genuinely fresh path — unchanged mechanism [DC-5]**: `admitted = candidate` bag-subtracted against the in-memory `violations_df` via the existing `frames/checks.py::violation_subtraction` — both sets are candidate-shaped in memory, so nothing forces hashing here, and the admit path stays UDF-free (A-7's cost claim holds because of this). Count identity asserted, unchanged.
4. **Guard-present path — hash-keyed [DC-5]**: the durable violation set is the read-back `row_hash` column for `(batch_id, "post_check")`; the recomputed candidates are hashed (the §7.3 UDF — the one admit-path UDF cost, paid only on reruns) and anti-joined. Keyed by hash because durable rows no longer carry candidate columns — the all-column anti-join is impossible on this path only. Drift stays data ([H-2], `post_check_drift` unchanged). Two subtraction mechanisms plus the shared door-2 demotion, each path paying only what it must — all registered to 006 as the interim it may replace.
