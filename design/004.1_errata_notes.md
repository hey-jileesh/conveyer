## 1. Errata to 004.1 (decision-record notes, no decision reversed)

1. **§7.6 `RunnerFx.append` signature is `(table, df, batch_id, stage_key)`,
   not the literal two-arg shape implied by the text.** The batch/stage
   snapshot-property stamp can't be reliably derived from `(table, df)`
   alone, especially for a legitimately empty `df`; shape matches
   `table_has_batch`'s existing `(table, batch_id, stage_key)` convention.
   (`conveyer-nvh.18`; `effects/records.py::RunnerFx.append` docstring.)
2. **`append` returns `(rows_appended, summary)`, never `(snapshot_id,
   summary)`.** `snapshot_id` is resolved on **both** the fresh-write and
   guard-skip paths via `resolve_batch_snapshot` (newest-first stamped-summary
   walk) — never read off the return value directly. (`conveyer-nvh.18`,
   `conveyer-nvh.20`.)
3. **§7.3 `run.py`'s pseudocode `stage.run(ctx, fx)` is resolved to
   `stage(ctx, fx)` (direct-call convention)** — `STAGES` holds callables,
   not objects with a `.run` method; the driver follows its own `STAGES`
   comment over the pseudocode's literal shape. (`conveyer-nvh.19`.)
4. **§7.0/§7.4 binding and structural-seed defects raise plain built-in
   exceptions, not `TransientError`.** Binding/namespace/arity failures and
   `run_facts`/`guards` structural violations are deterministic — retrying
   the same seed can never succeed, so they are allowed (by design) to burn
   Step Functions retries rather than being wrapped as transient.
   (`conveyer-nvh.19`.)
5. **§9/[H-2] the post_check read-back drift mismatch's RunFact outcome is
   `skipped-guard`, not literally `ok`.** [H-2]'s "surfaces in the ledger row
   on an ok outcome" is read as "on any non-failed outcome" — `ok`,
   `skipped-guard`, and `None` (no drift) are all covered by the same
   `error_message` channel; `failed` still wins and is never overwritten.
   (`conveyer-nvh.35`.)
6. **§6.3 `BatchContext` gains `post_check_drift: str | None`**, set by
   `post_check` on the read-back subtraction path and folded by
   `core/run_facts.py` into the ledger row's `error_message` on non-failed
   post_check rows — the minimal one-field channel [H-2] required; no
   generic annotation bag added. (`conveyer-nvh.35`.)
7. **§6.6/R-02: `state_snapshot_id` joins the declared attempt-truth
   exceptions.** A rerun whose fold is a logical no-op reports
   `state_snapshot_id = None`, which will generally differ from the original
   attempt's real snapshot id — R-02 must assert `None` explicitly on rerun
   rather than bare field-equality with the first attempt. **Recommendation
   for 008**: drop `state_snapshot_id` from the frozen `BatchCompletedV1`
   payload at freeze time rather than carrying this exception forward.
   (`conveyer-nvh.21`, `conveyer-nvh.22`.)

   > **Annotation [ECX-1]** (2026-09-01, bead `conveyer-6pg.33` — erratum
   > note per house convention; the original text above stands unaltered):
   > `fact_snapshot_id` (the payload's OTHER attempt-truth-exception field,
   > the same event-contract row this note extends) gains its own
   > None-widening under 007.1's N-table register (B10, bead
   > `conveyer-6pg.22`) — `stages/publish.py` derives it via `core.run_facts.
   > one_snapshot(...)`, `None` whenever zero or **more than one** declared
   > fact table produced a snapshot this attempt, not only on expiry. A
   > `None` `fact_snapshot_id` therefore no longer implies "no facts
   > committed this batch" the way a single-fact-type reading might assume
   > — `fact_count` (durable-read-back, always populated) is the field that
   > answers "were there facts," never `fact_snapshot_id`'s own nullity.
   > **Cross-lane consumers must not read `fact_snapshot_id is None` as "no
   > facts"** — the Optional contract's own widened meaning, not a decision
   > reversal (the field was already `int | None`; only the set of reasons
   > it can be `None` grew).

8. **I-19 MERGE own-commit attribution hardened: unique-child-of-`before_id`,
   never "current."** Original implementation read `<table>.refs`'s `main`
   head immediately after `MERGE INTO` returned and treated it as "our"
   commit — under concurrent sibling folds into the same state table, a
   sibling committing between our commit and that probe misattributes
   snapshot id + summary onto our batch. Fixed to capture `before_id` before
   the statement and resolve the unique child of `before_id` in
   `<table>.snapshots` afterward (invariant to how much later it's
   resolved). **Residual, named not assumed away**: if a sibling commits
   *before* our own `MERGE INTO` executes (same `before_id` as its live-read
   base), our successful commit's parent becomes the sibling's snapshot, not
   `before_id` — chain topology alone can't then disambiguate. Detected via a
   pre-commit `base_shifted` re-read comparison; reported as a **third,
   distinct result state** `MergeResult(None, None, attributable=False)`
   (not the same shape as a logical no-op) plus a `logger.warning`.
   **`attributable=False` is not yet threaded into `BatchContext`/the ledger
   row** — informational-only today, correctness never reads it; register
   with 007/008. (`conveyer-nvh.40` [F1]; `effects/spark.py::_build_merge`
   module + function docstrings.)
9. **§7.6/I-19 "MERGE may commit nothing" corrected: Iceberg MERGE always
   physically snapshots.** Empirically (Spark 3.5.9 / Iceberg 1.6.1, both
   copy-on-write and merge-on-read), a `MERGE INTO` with ≥1 MATCHED/NOT
   MATCHED row always commits a new child snapshot, even when nothing is
   inserted/updated. Logical no-op is detected via the resolved own-commit
   candidate's `changed-partition-count = "0"` in its Iceberg summary — never
   by diffing snapshot ids — and this signal is reliable **only** under
   `write.merge.mode = merge-on-read` on the target table (copy-on-write
   still converges correctly but never reports a no-op `MergeResult`).
   (`conveyer-nvh.18`; `effects/spark.py::_build_merge` module docstring.)
10. **§5 grammar recommendation: forbid a trailing segment dash.** Current
    per-segment grammar (`^[a-z0-9]([a-z0-9]|-(?!-))*$`) permits a segment to
    end in a single `-`, which forces `unslug`'s decoder to special-case a
    3-dash run (`"-/"`) at former `/` boundaries distinctly from the 2-dash
    separator alone — correct as shipped and property-tested (I-33's
    `injectivity` corpus), but TF's copy of the same grammar is currently
    **stricter** (rejects trailing dash) than the Python source, an
    unintentional divergence. Recommend converging by banning trailing
    dash in both, which would delete the 3-dash special case entirely.
    (`conveyer-nvh.43` [F5]; `core/naming.py` module comment above
    `_DASH_RUN_RE`.)
11. **I-P1 provisional reader: RFC-4180 doubled-quote fixed in-phase; two
    gaps remain, named not silently accepted.** `escape='"'` was required
    (Spark's CSV reader defaults `escape` to backslash) so that
    `csv.writer`-produced doubled-quote fields don't misparse as ragged rows
    and kill the whole batch under FAILFAST. Two residual gaps, both
    pre-existing and unaffected by the fix: (a) invalid UTF-8 is **never**
    caught by FAILFAST — Spark's decoder silently substitutes U+FFFD instead
    of raising; (b) newline-in-quotes is **not supported** —
    `multiLine` was deliberately left unset because enabling it would trade
    away FAILFAST's ability to catch a genuinely unclosed quote, and kill
    file splittability, for support of the separate embedded-newline case.
    Both are 005's to solve under real reader semantics (I-P1).
    (`conveyer-nvh.38`; `effects/spark.py::_build_read_objects` comment.)
12. **§11.1 metric table gains `RouterDetailOversized`; `PostCheckDrift`'s
    source moved to `record_run`.** `RouterDetailOversized` (the router's
    argv-budget-bound metric) was implemented but omitted from the §11.1
    table — documentation-only gap. `PostCheckDrift` is emitted from
    `record_run`'s implementation (derived from the `RunFact`'s
    `post_check_drift`/`error_message` field), not inline in `post_check.py`
    — consistent with §7.3's "stages contain zero instrumentation."
    (`conveyer-nvh.26`, `conveyer-nvh.43` [F4].)
13. **§12.2 exemplar transforms live in the shippable `pipelines.identity`
    package, not under `tests/`.** I-10's `^pipelines\.` import-namespace
    grammar makes a `tests/`-rooted exemplar module structurally
    unbindable (`binding.py` would reject it) — `pipelines/identity/` (and
    its `_violations` variant) ships in the spine distribution; only the
    YAML/fixtures/goldens stay under `tests/exemplar/identity/`.
    (`conveyer-nvh.22`.)
14. **`RunnerFx.read_objects` signature hardens to `(object_uris,
    ReadSpecModel, RawContractModel)`, retiring I-P1's untyped hints bag.**
    The provisional `Mapping[str, JsonValue]` hints parameter dies with
    I-P1's FAILFAST reader — the real reader needs the declared read spec
    and raw contract as typed inputs. Same implementation-forced-signature
    class as errata item 1 above. (`conveyer-azr` epic; 005.1 LLD §5.8;
    `effects/records.py::RunnerFx.read_objects`.)
15. **`frames/lineage.py::stamp_raw_lineage` gains a `read_spec_version:
    str` parameter.** Raw rows must carry the read-spec version that
    decoded them (005 D-1's auditability) — a raw-only lineage divergence
    from the fact-table lineage stamp, since only raw rows are a function
    of a read spec. (`conveyer-azr` epic; 005.1 LLD §5.9.)
16. **`BatchContext` gains `read_spec_version: str`, `check_version: str`,
    `pre_check_drift: str | None`.** `read_spec_version`/`check_version`
    are the admission-side content-hash version stamps (005 §13.1's
    "versions over the canonical parsed form", computed once at binding,
    stamped per row); `pre_check_drift` mirrors `post_check_drift` exactly
    (errata item 6 above's class) — folded into the ledger row's
    `error_message` on non-failed pre_check rows by the same
    `core/run_facts.py` machinery. (`conveyer-azr` epic; 005.1 LLD §3.5.)
17. **Linter (`tools/linter_configs/spine.py`): `expr` joins the
    string-SQL sinks, with one named exemption; `core/reading.py::
    parse_line` joins the core try-allowlist.** `expr` joins the
    `effects-stages` profile's string-SQL sinks, exempted at
    `("spine/frames/checks.py", "_typed_expr")` — and the
    `frames-transforms` profile applies the identical sink rule so the
    exemption is meaningful there too; `parse_line` joins
    `_TRY_RAISE_ALLOWLIST` (`csv.Error` → value), same shape as errata
    item 1's `core`-profile allowlist entries. (`conveyer-azr` epic;
    005.1 LLD §12.6.)
18. **`frames/checks.py::violation_subtraction` (the post_check
    all-column bag-subtract) is retained for the post_check fresh path
    [DC-5] — it is not deleted.** Only the guard-skip rerun's read-back
    subtraction changes mechanism, from the all-column anti-join to
    `row_hash`-keyed subtraction against the durable quarantine set for
    `(batch_id, "post_check")` (005.1 §8.2); the fresh path keeps bag
    subtraction unchanged, because both sides of that comparison stay
    candidate-shaped in memory. **This corrects an ambiguous phrasing in
    005.1 LLD §6.5** ("superseded by §8.2's hash subtraction — one
    deletion, not two mechanisms") that, read literally, could be
    misread as deleting `violation_subtraction` itself; the "one
    deletion" is the guard-skip call site's old subtraction call, not the
    function — A-14 keeps it live on the fresh path. I-12's "006 owns
    violation identity" now points at A-14's interim pair (fresh:
    bag-subtract; rerun: hash-keyed). (`conveyer-azr` epic; 005.1 LLD
    §15.3 item 5, §6.5, §8.2, A-14.)
19. **Per-type generalization (006 D-4): the singular `spec.fact_table` /
    `spec.state_table` / `ctx.candidate_facts_df` become per-fact-type
    families; the commit/fold soundness argument generalizes table-wise, no
    decision reversed.** 006 D-4 settles `apply(valid_df, co_effects) →
    {fact_type: candidate_df}` with one fact table (and one state table) per
    declared fact type, while §6.2/§6.3/§7.5 are written against singular
    fields and 004 D-4's one-commit soundness is argued per single table.
    Register: **commit = N guarded appends**, one per `(batch_id,
    fact_table)`; **fold = N MERGEs**, one per state table; the guard grain
    and the one-commit invariant become **per `(stage, table)`**; and 007
    D-2's zero-fact corollary holds **per-table** — a type all of whose
    candidates dropped leaves no guard row for *that* table only. Door
    semantics under partial multi-table presence (a kill between type
    appends): the **commit skip is per-table decide-then-do** — a
    batch-grain skip would silently lose the unwritten table's facts, the
    one loss class fail-open cannot absorb; the **`batch_check` demotion
    door (006 §5.4) demotes on ANY-table fact presence** — an all-tables
    reading would re-render the batch verdict against re-resolved co-effect
    snapshots with some facts durably committed, the [H-2] wedge the door
    exists to close. Also registered: §7.5's `ctx.transforms.post_check`
    call site is **superseded by the framework check interpreter** (006 D-1
    — pipelines contribute zero check code; `Transforms` loses the
    post_check member at 006.1), and 004's stage-diagram legend ("✱ = pure
    pipeline code (`apply`, `post_check`, optional `fold`)") is **stale**:
    post_check is declared data, not pipeline code (006 D-1), and fold is
    framework-owned in Phase 1 (007 D-3(e) bind-refuses custom folds) — a
    004 v1.x erratum candidate for `conveyer-ti0`. (`conveyer-3w8`; 006
    v1.0 D-1/D-4/§5.4; 007 v1.0 D-2/D-3.)
20. **§6.5 run-ledger accretion under per-type commit/fold (ADR-OQ5,
    Accepted): three additive per-table map columns land beside the
    existing map idiom; the singular columns are re-documented as attempt
    totals / one-snapshot forms; row grain, `outcome` vocabulary, and
    [E-9] all stand — additive-only (L-4), no decision reversed.** Item 19
    above made commit N guarded appends and fold N MERGEs, which falsifies
    the singular columns for a multi-type batch; ADR-OQ5 (Option D)
    evolves the ledger additively. New columns (all nullable, beside
    `co_effect_snapshot_ids` / `merge_summary`):
    **`facts_appended_by_table: map<string,long>`** — commit rows;
    per-fact-table appended counts of **this attempt**, with a `0` entry
    for each guard-skipped table (item 19's per-table decide-then-do: the
    skip is stated in the map, not silent);
    **`snapshot_ids_by_table: map<string,long>`** — commit **and** fold
    rows; the per-table snapshot this attempt produced, **absent key =
    skip/no-op** for that table;
    **`rows_merged_by_table: map<string,long>`** — fold rows;
    per-state-table merged counts. Singular columns, re-documented not
    retyped: `facts_appended` / `rows_merged` are **attempt totals** (sum
    over tables; `0` on a full guard-skip); `snapshot_id` /
    `merge_summary` follow **one symmetric rule** — populated when the
    stage produced exactly **one** snapshot, `NULL` when N > 1, per-table
    truth in the maps (a `map<string,string>` cannot carry N verbatim
    Iceberg summaries without key-prefixing; NULL-when-N>1 is truthful and
    additive, and this channel is attempt-truth — allowed lossy).
    `outcome` vocabulary unchanged: `skipped-guard` means **all** tables
    skipped; a mixed per-table run is `ok` with the story in the maps.
    §11.5 named-query sweep (ADR-OQ5 validation 2 — every query
    dispositioned by name; none breaks): `spine-run-status` (latest
    outcome per (batch, stage)) — outcome/stage grain, **unaffected**;
    `spine-attempts-per-batch` (distinct `attempt_id` counts) — attempt
    grain, **unaffected**; `spine-stage-durations-30d` (timing columns) —
    **unaffected**; `spine-rerun-noop-rate` (every row `skipped-guard`
    with `facts_appended = 0`) — **survives under totals semantics**: a
    full no-op rerun skips every table, so the outcome is `skipped-guard`
    and the total is `0`; note this at the query definition. The
    `BatchContext` per-table map fields feeding `record_run` are 007.1 §4
    field-level ground (same additive class as errata items 6/16 above) —
    cited, not specified here. Seam restated (L-1, one line): batch-truth
    lives in the marker table (007.1 F-9 — settled, §4.3 [DC2-1]); this
    ledger remains the lossy attempt-truth ops channel — control never
    reads it (004 §14.7 unchanged; [E-9] stands as accepted for
    attempt-truth).
    (`conveyer-hpp.13.12`; `design/adr-oq5-batch-progress-grain.md`
    (Accepted) L-1/L-4; item 19 above; 007.1 §4 / F-9 forward.)

## 2. Downstream register additions (by receiving LLD)

**005** (reader / raw contract):
- Reader semantics additions beyond I-P1's provisional FAILFAST: invalid
  UTF-8 is silently substituted (U+FFFD), never raised; newline-in-quotes is
  unsupported (RFC-4180 doubled-quote itself is already fixed — 005 inherits
  a *working* provisional reader, not a broken one). (`conveyer-nvh.38`.)
- **Quarantine shape is a LOAD-BEARING precondition of I-12's rerun-subtract
  mechanism**, not a free-standing schema choice: post_check's guard-skip
  path subtracts durable read-back quarantine rows from the candidate set,
  and this **fails open** (drift goes undetected, not loud) if pre_check's
  (raw-shaped) and post_check's (fact-shaped) violations diverge in table
  shape. Phase 1's identity exemplar only works because both stages share
  one quarantine table with a byte-identical projection — a real reshaping
  pipeline forces the same constraint on `apply`. Revisit explicitly at 005.
  (`conveyer-nvh.22`.)
- Partner-filename classification rule (unchanged from LLD §15.2 — carried
  forward, not new).

**006** (violation-keyed identity): unchanged from §15.2 — violation
identity for keyed subtraction, replacing I-12's all-column anti-join.

**007** (state/fold):
- State-table DDL **MUST** set `write.merge.mode = merge-on-read` — the
  hard precondition for no-op detection (errata #9 above); copy-on-write
  silently loses the no-op signal without failing loudly.
- Ordering columns **must be part of every current-state DDL** (already in
  §15.2 [H-6]) — reaffirmed as the same obligation, plus: custom-fold
  ordering-key resolution is **absent** in Phase 1 (default LWW is the only
  wired path); binding-time WARNING added when `spec.fold` is custom as the
  Phase-1 guard against silently-wrong ordering. (`conveyer-nvh.43` [F12].)
- MERGE commits are now the **unstamped commit class** — every other
  effectful write carries `conveyer.batch-id`/`conveyer.stage` snapshot
  properties (I-4), but a rendered `MERGE INTO` cannot set commit
  properties from PySpark; `CommitMetadata` threadlocal stamping was
  considered and rejected as impractical from PySpark (documented, not
  silently dropped). 007/009 should decide whether this gap needs closing.
  (`conveyer-nvh.40`.)
- One-row-per-`domain_id` cardinality (already a §15.2 precondition) is now
  a **named** defect at runtime: Spark's `MERGE_CARDINALITY_VIOLATION` is
  detected off the wrapped Java exception's own `getMessage()` and re-raised
  as a named `ValueError` ("fold cardinality defect ... I-11 [T-12]"), not a
  raw `Py4JJavaError` and not `TransientError` (deterministic; retry is
  wasted). (`conveyer-nvh.36`.)
- Run-ledger per-table accretion (errata item 20 above, ADR-OQ5): the
  `BatchContext` per-table map fields feeding `record_run` are 007.1 §4 /
  F-9 field-level ground; batch-truth lives in the marker table (F-9 —
  settled, 007.1 §4.3 [DC2-1]) — the ledger stays the attempt-truth
  channel (L-1), and nothing in item 20 adds a control read.
  (`conveyer-hpp.13.12`.)

**008** (payload freeze / maintenance):
- Drop `state_snapshot_id` from `BatchCompletedV1` at freeze (errata #7).
- Compaction clustering obligation carried forward unchanged from §15.2
  (`batch_id` clustering — guard-probe cost, `read_batch`, stamped-summary
  lineage all lean on it).
- Unattributable-merge ledger threading: `MergeResult.attributable=False`
  (errata #8) is not yet visible in the ledger row or `BatchContext` — 008
  should decide whether/how to thread it, since today it's WARNING-only.

**009** (pipeline authoring / IaC):
- `RunnerConfig`/`config.py`'s argv key names (`_ARGV_KEYS`) are pinned by

  names on the Terraform side rather than leaving two independently-authored

- Bootstrap-ledger Makefile target gap: no target wires initial run-ledger

- Co-effect grants: currently a **hand-authored TF variable list** at the

- `CONVEYER_SFN_ARN_PREFIX` / `ARGV_BUDGET_BYTES` env-shape needs 009

  (`conveyer-nvh.26`.)

## 3. Build-phase bug ledger (one line each)

- **Unslug injectivity**: naive `"--" → "/"` replace mis-decoded a 3-dash
  run at former `/` boundaries; fixed with an explicit 3-dash special case,
  property-tested. (`core/naming.py`.)
- **`.match` vs `.fullmatch` on `^...$` patterns**: Python's `$` matches just
  before a trailing `\n`, so `.match` silently accepted a batch_id/identifier
  with a trailing newline; switched to `.fullmatch` everywhere. (`core/naming.py`.)
- **`guard_skips` accretion gap**: `commit.py` and `post_check.py` omitted
  `guard_skips` accretion on the guard-skip path, which would have broken
  the `skipped-guard` ledger outcome; caught by the full-sequence R-02 run.
  (`conveyer-nvh.22`.)
- **Silent pull-ledger-row loss (P0)**: `effects/ledger.py::_row_from_run_fact`
  used `dataclasses.asdict`, whose deepcopy raises on `MappingProxyType`
  (pull's own deliberate immutable field) — swallowed by `record_run`'s outer
  catch with no WARNING and no `RunLedgerLoss` metric, every attempt, every
  pipeline. Fixed via explicit `dataclasses.fields` + `getattr` with
  `Mapping`→`dict` boundary conversion; `record_run` restructured so
  row-derivation failures now hit the WARNING/metric path instead of being
  silently absorbed. (`conveyer-nvh.36`; `effects/ledger.py::_row_from_run_fact`
  docstring.)
- **TF slug grammar stricter than Python post-replace validation**: same
  grammar authored twice, diverged on trailing-dash handling; named as
  errata #10 for convergence, not yet fixed. (`conveyer-nvh.43` [F5].)
- **`naming.py` importing from pydantic-shaped `model.py`**: broke
  `router.py`'s stdlib+boto3-only zip constraint (I-8) even though the
  reused symbols were themselves pure — the zip-purity test caught the
  transitive `import pydantic`. Fixed by inverting the dependency:
  `naming.py` is the single stdlib-pure source, `model.py` imports from it.
  (`conveyer-nvh.26`, `conveyer-nvh.43`.)
- **RFC-4180 doubled-quote CSV rows killed the whole batch**: Spark's CSV
  reader defaults `escape` to backslash, not the quote character; a
  well-formed `csv.writer` doubled-quote field misparsed as a ragged row
  under FAILFAST. Fixed with `escape='"'`; `multiLine` deliberately left
  unset (see errata #11). (`conveyer-nvh.38`.)
- **MERGE own-commit attribution race**: reading "current" snapshot
  immediately after `MERGE INTO` misattributed a sibling's concurrent commit
  to our own batch. Fixed via unique-child-of-`before_id` + pre-commit
  base-shift check; residual sub-statement race named and reported as a
  distinct `attributable=False` result rather than assumed away. (errata
  #8; `conveyer-nvh.40` [F1].)
- **EventBridge custom-bus resource policy was Allow-only**: same-account
  IAM union auth meant any principal in the account could `PutEvents` with a
  forged `source`; fixed with explicit `Deny` + `aws:PrincipalArn NotLike`
  statements mirroring the artifacts-bucket S3 policy pattern (3 Deny
  statements: forged-ingestion-source, forged-spine-source, deny-unknown-
  source). (`conveyer-nvh.41` [F2].)
- **Purity linter missed bare/intermediate attribute access**: only the
  outermost `Call.func.attr` was checked against `banned_attr_names`, so a
  chained access like `df.sparkSession.read.parquet(...)` passed the linter
