### P-1 — The declaration surface is a per-type mapping in one content-pinned spec value; the fact-column grammar is the canonical value domain; `Transforms` shrinks to `apply` (+ optional `fold`) — **settled**

In the context of hardening D-4's declared surfaces (`apply → {fact_type: candidate_df}`, fact schemas with `domain_id_col`/`record_key:`/`ordering:`) and errata row 19's per-type register into runner-consumed models, facing the A-12 precedent (runner model now, authored surface frozen at 009) and 007.1 F-4's requirement of a total, deploy-pinned fact-type iteration order, **we chose**: `PipelineSpecModel` drops the singular `fact_table`/`state_table` and gains `fact_types: dict[str, FactTypeModel]` (min 1) — one entry per declared type carrying that type's fact table, state table, and `FactSchemaModel`; iteration order = declaration order in the spec file, preserved by the parsed insertion-ordered mapping and made deploy-stable by the content-pinned deployed spec (004.1 I-23) — F-4's total order with no new mechanism; the fact-column **type grammar is exactly the canonical value domain**: `string | int | long | bool | decimal(p,s) | date | timestamp` — no format parameters (candidates are already typed; parsing was admission's), and **float/double are structurally unrepresentable** (007.1 §5.1 fragment 3's handed constraint: `canonical_json` rejects floats and 007 D-1 hashes every declared column); **no per-column `nullable` claims in Phase 1** — all declared fact columns are nullable in DDL, a business non-null requirement is admission's `nullable: false` or an authored row check (`col IS NOT NULL` with a `business/…` reason), and `domain_id_col` null-ness is framework ground (the implicit check, D-6/007 D-3(d)); `Transforms` **loses the `post_check` member** (errata row 19: the call site is superseded by the framework interpreter) and `apply`'s bound signature becomes `(valid_df, co_effects) -> Mapping[str, DataFrame]`; the whole surface migrates as a **hard cut** (A-12's idiom — one exemplar consumer, no deprecation window), **and rejected** keeping singular table fields with a side per-type mapping (two sources for one enumeration — the door planner and the commit loop must read the same set), **and rejected** per-column `nullable` on fact schemas now (a claim with no Phase-1 consumer — DDL is all-nullable, candidate-defect checking is shape+types, and a `nullable: false` on `domain_id_col` would re-complect the demotion 007 D-3(d) settled: batch death and quarantine cannot both own the same null), **and rejected** separate deployed artifacts per declared surface (the runner consumes one content-pinned value; multi-file layout is the *authored* shape, 009's §6.2 preview — build-time assembly is 009's ground), **to achieve** one enumeration every consumer reads (doors §8, commit/fold iteration 007.1 F-4, IAM generation S-15, [H-6] DDL generation), a type grammar under which every declared column is hashable and renderable by construction, and a transforms surface reduced to the only code a pipeline contributes, **accepting** the hard-cut migration cost (exemplar + deployed dev spec, §14), and that a YAML reordering of `fact_types` changes commit iteration order — semantically inert (each (stage, table) pair is independently sound, F-4) but recorded, since the deployed spec is content-pinned and any reorder is a reviewed diff.

### P-2 — The gatekeeper is a fail-closed AST walk over an exact-pinned sqlglot parse, backed by an engine compile gate; the allowlist is a versioned data module pinned by an executable semantics table — **settled**

In the context of 006 §5.2's mandate (bind-time validation against a pinned function allowlist; a rejected expression is a bind defect) facing the enforcement question the epic names as weak ground — *how* an authored expression is proven inside the subset — and facing the two-evaluators trap (005.1 A-7's class: any second parser can disagree with the executing engine), **we chose** a two-gate design: **(gate 1)** parse the authored text with **sqlglot (dialect `spark`, exact-pinned `==` version)** and walk the AST **fail-closed** — every node must be in the enumerated allowed-node set and every function name in the allowlist, where the allowed set is defined against the **pinned parser's actual parse shapes** and backed by **per-node structural predicates** (§6.4 [EM-2] — pure node-kind enumeration cannot be built: the parser gives `DATE '…'` and `int(x)` the same `Cast` node kind [EM-1], normalizes `nvl`→`Coalesce` and `ltrim`→`Trim`, and gives `1.245E2` the same node kind as `1.245`); anything unrecognized, including node kinds sqlglot adds in future versions, rejects — subqueries, windows, lambdas/HOFs, cast syntax in every authorable spelling (`CAST(…)`/`::` parse as `TryCast`, rejected in every shape; constructor casts `int(x)`/`double(x)` are non-typed-literal-shaped `Cast`, rejected — the one admitted `Cast` shape is §6.1's typed-literal carve-out [EM-1]), interval literals, parameters, and stars are rejected *because they are not in the allowed set*, not because they are on a ban list; string literals are values whose contents are never re-parsed, so "SQL smuggled inside a string" is inert by construction; **(gate 2)** compile the accepted text against an empty DataFrame bearing the bound fact type's schema (`df.select(F.expr(text))`) at bind — the [DC-4] idiom (best-effort independent check + executing-engine-normative compile), so a sqlglot-accepts/Spark-rejects divergence surfaces as a **bind** defect, never a stage-time `AnalysisException` — and the text gate 2 compiles is the **authored text, byte-exact**, the same string stage-time `F.expr` receives (§6.4's executed-text rule [EM-6][AE-2]: sqlglot is judge and extractor, never renderer-into-execution); gate 2's compiled plan additionally serves as P-9's type oracle (§6.5 rule 2); the allowlist itself is a **versioned data module** (`core/check_grammar.py`: `CHECK_GRAMMAR_VERSION`, allowed node kinds, scalar functions with arity + event-lane portability notes, aggregate functions for the `batch_check` position) whose every entry is **CI-pinned by an executable semantics table** (A-15's idiom, §13 G-08): each allowlisted construct has at least one vector row evaluated on the real engine under the 005.1 §6.2 session pins, so an engine or sqlglot upgrade that shifts any semantics fails CI, not production, **and rejected** raw Spark SQL acceptance (006 §5.2's own argument — `rand()`, windows, subqueries return D-1's hole through one string), **and rejected** the Spark parser as the gatekeeper (private py4j API, JVM tree-walking, and grammar semantics that version with the engine — the D-6(c) complection admission already refused in DQDL), **and rejected** regex/token scanning of the text (a blocklist scan fails *open* on creative syntax — the exact back door), **and rejected** a bespoke expression mini-language (a second language to specify, parse, and teach in both lanes; subset-SQL is the smallest surface two interpreters can share, and Track A's vectors — §13's check-verdict convention — are the cross-lane guarantee either way), **to achieve** an authored surface provably inside the deterministic subset before any effect, with grammar growth as a reviewed data-module diff plus its A-15 rows, **accepting** one new exact-pinned pure-Python dependency whose parse behavior is semantics-adjacent (mitigated by fail-closed enumeration, the compile gate, and the executable table), and the named residual that gate 2 runs per (expression, fact type) at bind — a few empty-plan analyses per run, pre-land, seconds-class.

### P-3 — One `check_version` column, sourced per stage; per-check content hashes in `reason_detail`; `checks_version` accretes at binding — **settled (rules OQ-4)**

In the context of business-check version identity (D-6: `reason_detail` carries check ids *and versions*; 005.1 A-11 defines `check_version` as the pair-hash of `{raw_contract, read_spec}`), facing OQ-4's choice — fuse checks.yaml into a stamped triple vs. a second stamped column — **we chose** per-stage sourcing of the **existing single column**: on `check_stage = 'pre_check'` rows, `check_version` stays A-11's pair-hash, unchanged; on `check_stage = 'post_check'` rows, `check_version` = **`checks_version`** = sha256 (lowercase hex, full) of `canonical_json` of the parsed `ChecksModel` — computed once at binding, carried as a seed-adjacent `BatchContext` field (the A-11 idiom exactly), stamped by the post writer; the column's meaning — *the version of the declared surface whose checks this row's stage evaluates* — is a deterministic function of `check_stage`, which the row already carries; per-check identity inside `reason_detail` is a **per-check content hash** — sha256 of `canonical_json` of that check's parsed `CheckModel` — so an entry survives unrelated edits to sibling checks and "which version of *this* rule fired" is a value on the row; the framework-reserved implicit check (D-6) carries the literal version `"fw-1"` (a governed constant, bumped only if its semantics ever change); `CHECK_GRAMMAR_VERSION` is **excluded** from `checks_version`'s hashed object (grammar releases are additive and semantics-pinned by A-15; the executing artifact is already content-pinned per I-23, resolvable via `attempt_id` → job run → wheel), **and rejected** the fused triple (a checks.yaml edit would re-version *pre_check* rows whose admission surface never moved — false provenance churn complecting two surfaces' version histories into one stamp, breaking A-11's "which declared surface rejected this row" in the one direction it currently answers cleanly), **and rejected** a second stamped column (an Iceberg DDL change to the deliberately versionless one-shape constant — 005.1 §4.4 fails loudly on any quarantine schema diff by design — buying a distinction `check_stage` already carries), **to achieve** version-as-a-column for every governed surface (006 §6.3's invariant) with zero DDL change and no false churn, **accepting** that a reader of `check_version` must know the per-stage sourcing rule (documented at the column, §16.3's 005.1 erratum) and that the full 64-hex per-check hashes make `reason_detail` a few hundred bytes per multi-failure row — bounded by the existing 32-entry truncation, dictionary-encoded to little.

### P-4 — One bind step, pre-land: effectful acquisition to plain values, pure validation, plain-`ValueError` defects — **settled**

In the context of placing the bind-time validator inventory (§5), facing the fact that co-effect checks need catalog reads (existence, class, schema) while the validators themselves must stay pure and property-testable, **we chose** the decide-then-do split applied to validation: the entrypoint, after spec parse and `bind_transforms` and session build but **before `land`**, acquires `CatalogFacts` — for every table the spec references (co-effects; fact/state tables for existence-only): `exists`, `table_class` (the `conveyer.table-class` property, §5.2), `columns` (name → type) — via one additive effect `fx.describe_table(name) -> TableFacts | None` (004.1-erratum class, §16.4), then calls pure `core/bind_checks.py::validate_bindings(spec, catalog_facts, transforms_meta) -> tuple[BindDefect, ...]`; any defect raises plain `ValueError` with the pinned message grammar **`bind-defect/<code>: <machine detail>`** — the A-10 class exactly: deterministic, pre-land, no raw write, no `batch-started`, no ledger rows, SFN retries burn loudly, alarm fires; messages are value-free and URI-free (tables by declared alias/identifier, columns by name), **and rejected** validating inside `binding.py`'s importlib step (transforms binding is pure of catalog concerns; complecting them makes the pure half untestable without a catalog), **and rejected** lazy per-stage validation (a co-effect defect discovered at `pull` has already landed raw and emitted `batch-started` — 004.1 §9's pre-land class exists precisely so misconfiguration never half-starts a batch), **to achieve** a validation core that is a total function over plain values (every §5 row property-testable without Spark) and a defect surface indistinguishable in class from admission's, **accepting** a few seconds of pre-land catalog reads per run and the new `RunnerFx` field. **Least-privilege pin [DS-6]:** `describe_table` requires **no new IAM objects** — it operates entirely within I-21's existing per-table grants (own `<slug>__*` tables via `Get*`; declared co-effects via the S-15-generated read-only grants); a bind-time `AccessDenied` on a declared co-effect is the **S-15 provisioning signal** — the grant generation has not run for that spec — and is never cause to widen catalog read (§16.4's obligation states this for the build).

### P-5 — Every check binds to exactly one declared fact type; evaluation and authored order read per type — **settled (rules OQ-3, coordinator-directed)**

In the context of OQ-3 — 006 §5.1's check kinds predate D-4's per-type return shape, leaving unstated which candidate frame a check evaluates over — facing the fact that a column reference is meaningless without a relation to resolve it against, **we chose**: every declared check (all three kinds) carries a required **`fact_type:`** field naming exactly one declared fact type; a check evaluates over that type's candidate frame only; bind-time column coherence is per type (every column the check references ⊆ that type's declared columns, §5.4); D-6's "authored order in the checks file is evaluation order" reads **per type** — the order of a type's checks is their relative authored order, and `reason_code` = first failure among *that type's* checks (a candidate row exists in exactly one type's frame, so no cross-type ambiguity exists); `batch_check` binds to a fact type like any other (its aggregate runs over that type's candidate set; its control member is admission's ground, §9); the field is **required even for single-type pipelines** (D-4's own acceptance — explicitness costs a one-token annotation; the runner model is not the authored surface, and 009 may add sugar), **and rejected** evaluating checks over a union of the typed frames (re-complects the heterogeneous relations D-4's mixed-`facts_df` rejection separated; column resolution becomes ambiguous the moment two types share a name), **and rejected** per-check fact-type *lists* (a rule over N types is N declared checks today — trivially authorable — while a genuinely cross-type rule is cross-frame judgment, a **new kind** under the growth rule, not a binding annotation), **and rejected** blocking on a 006 erratum first (the coordinator ruling: settle here; the binding is additive authoring-surface grain that changes no settled semantics), **to achieve** checks whose column references are decidable at bind and whose evaluation-order law survives multi-type pipelines unweakened, **accepting** the one-line ceremony per check and a **candidate 006 erratum** (registered §16.5, not blocking): §5.1's kind table and D-6's order law acquire the per-type reading.

### P-6 — The `batch_check` control seam is designed against a pinned member-grammar interface; until that grammar lands, any `batch_check` is a bind defect — **settled**

In the context of D-5's LLD grain (control extraction; the exactly-one-summary-row expectation) facing the explicit upstream wait — 005 v1.x's delivery-member grammar does not exist, and 006 §8 already accepts that two-member feeds cannot build until it does — **we chose** to pin the **interface this doc requires** of that grammar, and nothing of its mechanics: (i) a **member-scoped admitted-rows accessor** — given a declared member name, the post_check stage can obtain that member's *admitted* rows for this batch (typed under the member's contract, quarantine-subtracted), derived from durable raw + the member's declared surfaces with no new I/O class; (ii) member declarations visible in the parsed spec so the **coherence rule is bind-checkable**: a member referenced as a `batch_check` control source must be `required: true` (006 §7's rule — a check that cannot evaluate must be an inexpressible spec, never a silent skip); (iii) **stage-order precedence** — the control member's own admission (contract, quarantine) completes before any `batch_check` evaluates (already guaranteed by the stage sequence; restated as an interface property); control extraction itself is a declared `control: {member: <name>, expr: <scalar expr>}` — the extraction expression is scalar-position under §6's allowlist, evaluated against the control member's single admitted row; and **the structural wait**: until the member grammar lands, a `checks.yaml` declaring any `batch_check` is a **bind defect** (`bind-defect/batch-check-awaiting-member-grammar`) — the kind is fully specified here and bind-dormant, the D-3 refusal idiom (the unsupported state is unrepresentable in a bound pipeline, not documented around), **and rejected** sketching the member grammar here (the epic non-goal and the drafting plan's named risk — 005 v1.x/009 ground), **and rejected** a literal/constant control source as an interim (D-5 settled control values come from sibling-member admitted rows; an interim second source would be a second control semantics to retire), **to achieve** a seam 005 v1.x can implement against a written interface, with the first customer's expectations (carrier-x detail/summary) already pinned, **accepting** that `batch_check` ships dormant — exactly the state 006's falsifier record left it in (unexercised, first customer awaiting the same grammar). **The exactly-one-summary-row expectation, verdicts pinned:** the control extraction requires exactly one admitted row of the control member; **0 rows** decomposes into (a) member absent — unreachable: the coherence rule makes the control member `required`, and a missing required member is admission's tier-1 `missing-required-member` defect, so the batch died before post_check; (b) member present but its rows all quarantined at admission (the summary row failed its own contract) — **`batch_check` fails loud with the distinct named failure `control-unavailable`** (data-driven: the control cell was bad; remediation is a corrected delivery), never a silent skip and never conflated with a reconciliation mismatch; (c) **member present, zero rows delivered [AE-5]** — a header-only object passes admission (005.1 A-16: the probe passes, the zero-row append commits, admission completes), so zero rows are admitted *and* zero quarantined, reaching the `count == 1` assertion as 0 through neither (a) nor (b) — **fails as `control-unavailable`**, the same data-driven class and remediation; whether `required` should mean *non-empty* — which would surface this case tier-1 at admission and make (c) unreachable — is a 005 v1.x member-grammar decision, registered §16.6 [AE-5], with (c)'s verdict standing as the floor either way; **exactly 1 row whose extracted control value is NULL** — **`control-unavailable`** as well ([AE-4], semantics restated at §7.5: the control cell is absent/bad — not a mismatch, nothing was compared; not (b), nothing was quarantined); **>1 rows** — **fails loud as `control-ambiguous`** (which row is the total is not decidable; per-group summaries are the named grouped-`batch_check` growth, 006 §5.1) — and **value-identical duplicate control rows are deliberately conflated into this verdict [AE-11]**: a summary line shipped twice byte-identical admits twice (admission has no intra-batch dedup; value-identity collapse is 007's fact-side mechanism) and fires `control-ambiguous` although the value is decidable — strictness over special-casing, stated so 009's guidance and 012's queue view can explain the verdict to an operator whose control value was never ambiguous; DISTINCT-collapse is a named possible refinement, never silent behavior. All of these, like every `batch_check` verdict, demote to the drift probe when facts are present (§8.4).

### P-7 — Fact-presence doors probe ANY declared fact table through one pure planner; the post-quarantine hash subject carries a reserved fact-type tag; the fresh path is one evaluation, two outputs — **settled**

In the context of §5.4's mechanics at per-type grain (errata row 19; door semantics assigned normatively to this doc by 007.1 §7.1), facing two constructions surfaced while hardening: **(1)** after a kill between type appends, *some* facts are durably committed — any door that re-renders verdicts (row quarantine or batch failure) against re-resolved co-effect snapshots while part of the batch's facts are durable is the [H-2] wedge re-opened; **(2)** the durable `row_hash` set for `(batch_id, "post_check")` is undifferentiated across fact types, while the rerun subtraction runs per typed candidate frame — two declared types with identical column sets can hold value-identical rows, and a type-A quarantine row's hash would silently subtract an innocent type-B candidate: neither fact nor quarantine, the one silent-drop class this architecture exists to exclude — **we chose**: **(a)** all three fact-presence doors — pre_check's [DC-1] door, post_check's [R2-1] row door, and the `batch_check` demotion probe — evaluate **presence in ANY declared fact table** (`any(table_has_batch(t, batch_id) for t in fact tables)`), composed by one pure planner (`core/doors.py`, §8.2) whose enumeration input is P-1's `fact_types` mapping (the same enumeration 007.1 §7.1 iterates) and whose probe primitive is the existing `table_has_batch` per table — durable state is authoritative the moment *any* of it exists, because the verdict that admitted those facts was already rendered once, and a partial commit must **complete** (007.1 F-4's per-table skip), never **re-adjudicate**; **(b)** the post_check snapshot subject gains one reserved key: **`_conveyer_fact_type`** — the snapshot object becomes `{<declared cols…>, "_conveyer_fact_type": "<type>"}` (the reserved prefix is already collision-proof: [DC-6] bars it from contract columns and §5.4 bars it from fact columns), so `row_hash` discriminates relation membership exactly as `record_key` discriminates column names (007.1 F-2: the hashed object is the map, not the value tuple — the same principle one level up: *which relation* is part of the value's shape), and the per-type anti-join is sound against the one durable set with zero quarantine DDL change; **(c)** the fresh path implements [DC-5]'s ratified semantics — an in-memory, multiplicity-preserving, complementary split of candidates with the count identity asserted — as **one evaluation, two outputs per type** (005.1 §6.3's idiom applied to candidates): the framework-compiled checks produce a failures column, `admitted_t` = empty-failures filter, `violations_t` = non-empty filter; `frames/checks.py::violation_subtraction` is **retired** — its remaining call site existed only because the interim `post_check` returned an opaque pipeline-computed frame that had to be subtracted; framework-computed verdicts make the split and the subtraction the same plan, **and rejected** ALL-tables door reading (re-renders verdicts in exactly the partial-kill window — errata row 19's named wedge), **and rejected** a fact-type discriminator *column* on quarantine (a one-shape DDL change where a snapshot key suffices; the type rides `row_snapshot` and is `json_extract`-projectable for 012), **and rejected** arguing the cross-type collision away as improbable (two types legitimately share schemas — a detail/adjustment split is the resident counterexample class; correctness by construction beats correctness by schema diversity), **to achieve** doors that compose per-table mechanics (007.1's) with batch-grain authority (this doc's) under every kill interleaving, and a rerun subtraction sound per type against one durable set, **accepting** one snapshot-content change (an additive reserved key — proposed as a 005.1 §7.1 erratum, §16.3; committed vectors gain post-structure cases before any code ships) and that pre-tag durable quarantine rows in the dev exemplar are re-created rather than migrated (dev-disposable, §14).

### P-8 — Membership never fires on NULL key material; the plan is a left join against the distinct projection; multi-column is tuple equality — **settled**

In the context of membership-check mechanics (006 §5.1's second kind) facing SQL's three-valued traps (`NOT IN` over NULLs; NULL never equal to anything), **we chose**: **declared verdict semantics first** — a row with NULL in *any* of its membership columns **does not fire** the check (vacuous pass): null-handling is exactly one check's job (005.1 §6.1's law, applied one stage later) — non-null enforcement is admission's `nullable: false` or an authored `IS NOT NULL` row check with its own reason; a row fires iff all its membership columns are non-null **and** the tuple `(c1…ck)` has no match in the co-effect's referenced columns `(r1…rk)`; **the plan**: per membership check, left-join the candidate frame to the **`DISTINCT`** projection of the co-effect's referenced columns (distinct is load-bearing — a non-distinct reference would multiply candidate rows and corrupt every count downstream) on pairwise equality, marker column `_conveyer_m_<check_id>` (reserved prefix; dropped before frames exit), fired = all-cols-non-null ∧ marker IS NULL; the markers then compose into the same failures array as row-check booleans (§7.2), preserving one-evaluation-two-outputs; join strategy is left to AQE (reference tables are current-state folds, typically broadcast-size; no explicit hint in Phase 1 — an engine-review note, §13), **and rejected** `IN`-subquery rendering (string SQL where a plan-native join suffices; the linter's sink rules stay clean), **and rejected** null-fails semantics (complects two judgments — "is it present" and "is it null" — into one reason code, and resurrects the `NOT IN` trap in authored form), **and rejected** null-safe-equal matching (`<=>` would make NULL a *member value*, silently equating "unknown" with a reference row's NULL — an epistemic lie), **to achieve** value-determined verdicts (row value + pinned co-effect snapshot — 006 §5.1's table row holds) with SQL's null pathologies structurally unreachable, **accepting** one join per membership check per batch (bounded by the checks file; candidates are one batch's rows) and the 009 authoring note that membership silently passes null-keyed rows — by design, with the remedy named.

### P-9 — Authored expressions are family-typed at parse and dtype-checked at bind; `batch_check` comparisons are integral/decimal by construction — **settled** (review integration: the one decision answering [AE-1] + [EM-3])

In the context of two verified holes in the two-gate design — **(1)** under the pinned ANSI-off session a string-vs-numeric comparison coerces **both** sides to DOUBLE, so `amount != '9007199254740993'` over a `decimal(38,0)` column passes both gates (every node allowed: column, comparison, string literal) yet quarantines an innocent `9007199254740992` row at double precision ([AE-1]'s 2⁵³ construction — an engine-inserted cast the author never wrote, the exact silent-cast class the `CAST` exclusion claims closed; same class: `coalesce(dec_col, 'x')`, `BETWEEN` over mixed literal families, `length(int_col)`), and **(2)** `/` over integral operands and `avg` over int/long columns compile to DOUBLE on the pinned engine (verified: `avg(long)` → double, `4/2` → 2.0 double), so an allowlisted `avg(qty)` or `sum(a)/count(1)` puts binary floating point into §7.5's exact decimal comparison ([EM-3] — falsifying "no float ever enters") — facing the two-evaluators trap that forbids re-implementing Spark's coercion calculus in a second engine, **we chose** two rules with two oracles, both bind-time, both fail-closed: **(rule 1 — family coherence, parse-phase [AE-1])** the gatekeeper's walk computes a **family** for every accepted node bottom-up over the coarse partition `{string, numeric (int|long|decimal), temporal (date|timestamp), boolean}` — column refs from the bound type's declared schema (K3's ground), literals from their literal form, `NULL` polymorphic, functions from per-entry **family signatures** riding the §6 data module beside arity — and rejects any comparison, arithmetic, `IN`, `BETWEEN`, or function-argument site where **string meets numeric or temporal** (and any argument violating its signature) as `bind-defect/check-expression-mixed-types`: the author compares like with like, typed literals (`DATE '…'`) being the authorable way to compare temporals; the calculus is deliberately coarse — a *restriction on authorship*, never a prediction of engine semantics: everything it admits is evaluated by Spark alone, everything cross-family is refused before Spark could coerce it, so it cannot diverge from the engine in the direction that matters; **(rule 2 — compiled-dtype inspection, bind-phase [EM-3])** gate 2's compiled plan is the type oracle ([DC-4]'s engine-normative half, extended from "does it compile" to "what type did the engine give it"): a row `expr` must compile to BOOLEAN (`check-expression-not-boolean` — a non-boolean row check is a meaningless verdict, caught at bind rather than as a stage-time surprise) and a `batch_check` `aggregate`/`control.expr` must compile to an **integral or decimal** type (`check-expression-inexact-type`) — admitting `avg` and `/` over decimal operands (engine-verified: `avg(decimal(38,2))` → `decimal(38,6)`, `sum(decimal)/count(1)` → decimal) while refusing exactly the DOUBLE producers (`avg(int|long)`, `/` over integrals, `sum(net * '2')` — the last already dead at rule 1), keeping §7.5's exactness invariant true by construction, **and rejected** pinning the coercion semantics instead ([AE-1]'s own weaker option — G-08 rows for the 2⁵³ case plus authoring warnings — documents a wrong-verdict class instead of excluding it, against the doc's fail-closed posture), **and rejected** a full second type checker (precision/scale/result-type inference re-implements the engine's calculus and *will* drift; families plus the engine's own dtype answer cover every verified hole while predicting nothing), **and rejected** banning `/` and `avg` outright (decimal operands are exact on this engine and are the reconciliation workload's native types), **to achieve** authored checks whose comparisons are like-with-like by construction and batch verdicts in exact arithmetic with the engine itself as the type witness, **accepting** that an average over an *integral* column is inexpressible (declare the column decimal, or reconcile `sum` and `count` as separate checks — §6.3), that temporal-vs-string comparisons now require typed literals (a one-token authoring cost, §16.1), and the named residual that **row-position** arithmetic may still route through DOUBLE intermediates (`int_col / 2 > 0.5` — engine-deterministic, G-08-pinned; the exactness rule binds where exactness is load-bearing: the batch comparison).

**Y-note [DC-3] (de-critique gate `conveyer-hpp.5`) — the family-signature set's one normative home, chosen:** rule 1's per-function argument/result family signatures are **build-time data-module content** (`check_grammar.py` entries, beside arity — §6.5 rule 1) under a **corpus obligation**: every §6.2/§6.3 function ships with **at least one G-07 accept row conforming to its signature and at least one G-07 reject row per argument position exercising a cross-family operand** (§6.4/§13.1), so the committed corpus — never an implementation opinion — is where signature content is visible and adjudicated, and signature growth or drift is a reviewed corpus diff, extending the idiom §6.4 already uses for the allowed-node set [AE-8]. The alternative arm — a signatures column on §6.2's table — was **rejected**: that table is class-grain (multi-member rows with dense semantics cells), a per-function line would either restructure it or bury normative signatures inside prose, and it would open a second normative home beside the corpus for content the corpus must pin anyway. The initial corpus **must cover the review's named divergence points**: `concat`'s argument families, `replace`/`substring` result families feeding enclosing comparisons, `greatest`/`least` argument homogeneity, and `nullif`'s polymorphism. Divergence between two builders was already fail-closed (the safe direction); this note removes the spec-silence — which authored checks bind is now decidable from one committed artifact.

## 4. Contracts & Data Model (P-1)

All boundary models are pydantic v2 in `spine/core/model.py`, `extra="forbid"`, exported to JSON Schema and drift-gated (`make -C spine schemas`). Internal values are frozen dataclasses. The spec parse gains a **duplicate-key-rejecting YAML loader** (a small SafeLoader hook): a YAML mapping with duplicate keys is a spec-parse defect, not a silent last-wins — without it, D-2's "duplicate aliases rejected" is unenforceable (the parsed dict never sees the duplicate).

### 4.1 `FactSchemaModel` and the fact-column type grammar

```python
FACT_COLUMN_TYPE_RE = (
    r"^(string|int|long|bool"
    r"|decimal\([1-9][0-9]?,(0|[1-9][0-9]?)\)"
    r"|date|timestamp)$"                       # NO float/double: canonical value domain
)                                              # (007.1 §5.1 fragment 3); no fmt params —
                                               # candidates are typed, parsing was admission's

class FactColumnSpec(BaseModel):
    model_config = ConfigDict(extra="forbid")

    type: str = Field(pattern=FACT_COLUMN_TYPE_RE)

class FactSchemaModel(BaseModel):

    domain_id_col: str
    record_key: list[str] = Field(min_length=1)   # dedup identity participants (007 D-2)

```

Model validators (spec-parse-time): column names unique, disjoint from the **framework fact-stamp set** (`spine/core/record.py::FACT_STAMP_COLUMNS` — normative enumeration in **007.1 §5.1 fragment 4**, consumed as the one constant, never re-enumerated here) and from the `_conveyer_` prefix ([DC-6] extended; also what keeps §8.2's snapshot tag collision-proof); `domain_id_col ∈ columns`; `record_key ⊆ columns`; `ordering ⊆ columns`; `decimal` precision ≥ scale, ≤ 38 ([DC-10]). ### 4.2 `ChecksModel` and the per-kind check models

class BatchControlModel(BaseModel):

Authored order in `checks` **is** evaluation order (D-6), read per fact type (P-5). ## 6. The Expression Subset — Allowlist, Concrete (P-2)

`spine/core/check_grammar.py` — a versioned data module: `CHECK_GRAMMAR_VERSION = 1`; the sets below are its initial content. Growth is a reviewed diff to this module **plus** its A-15 rows (G-08) plus a cross-lane portability note — 006 §8's "every allowlist addition is a semantics decision," made mechanical.

### 6.1 Allowed node kinds (fail-closed enumeration)

Column reference (bound-schema columns only, K3) · literals: string, integer, decimal, boolean, `NULL`, `DATE '…'`, `TIMESTAMP '…'` (**float/double literals rejected**, scientific notation included — a literal-**text** structural predicate, since the pinned parser gives `1.245E2` the same node kind as `1.245` [EM-2]; outside the canonical value domain, consistent with §4.1/F-6) · parentheses · the operators and constructs of §6.2 · function calls whose name ∈ §6.2/§6.3 with correct arity.

**The one `Cast` shape carve-out [EM-1].** On the pinned parser, `DATE '…'`/`TIMESTAMP '…'` parse as `exp.Cast` nodes — the *same node kind* as the banned `int(x)` — while `CAST(x AS T)` and `x::t` parse as `exp.TryCast`; pure node-kind enumeration therefore cannot both admit the typed literals and reject casts. The allowed set admits `Cast` in **exactly the typed-literal shape** (`this` = string `Literal` **and** `to` ∈ {DATE, TIMESTAMP}) — which also admits the structurally identical spelling `date('2026-01-01')`, the same value, noted as such — and rejects `Cast` in every other shape and `TryCast` in every shape. The accept/reject parse shapes are pinned in the G-07 corpus.

**Everything else rejects** — named non-members, for the reviewer: subqueries, window specs, lambdas/HOFs, cast syntax outside the carve-out (`CAST(…)`, `::`, `int(x)`, `double(x)`), typed-literal **suffix forms** (`1.5D`, `1.5F`, `1.5BD`, `123L`) and keyword typed literals other than `DATE`/`TIMESTAMP` (`DOUBLE '1.5'` et al.) — each pinned as its own G-07 reject row, so the corpus, not an assumption about the parser's AST for each spelling, is the enforcement [AE-8] — `INTERVAL`, `*` (row counts are authored as `count(1)`, §6.3 [EM-9]), `DISTINCT`, parameters, semi-structured access.

### 6.2 Scalar position (row `expr`, `control.expr`, and argument positions)

| Class | Members | Semantics notes (A-15-pinned, G-08) |
|---|---|---|
| Arithmetic | `+ - * / %`, unary `-` | **ANSI-off pin dependence [EM-10]**: `/ 0` → NULL **and** `% 0` → NULL (a NULL verdict passes — §7.2's law; under ANSI-on both throw); decimal widening per Spark 3.5; operands family-checked (P-9 rule 1); `/` over integral operands is DOUBLE-typed — unreachable in batch positions (P-9 rule 2 [EM-3]), a named G-08-pinned residual in row position |
| Comparison | `= != < <= > >= <=>` | decimal comparison is numeric, scale-insensitive (`1.2 = 1.20` — F-6-consistent); `<=>` is the one null-safe form, included deliberately; operands family-checked (P-9 rule 1 [AE-1] — a string never meets a numeric/temporal: ANSI-off would silently coerce both sides to DOUBLE, the engine-inserted cast the gates exist to exclude) |
| Boolean | `AND OR NOT` | three-valued; §7.2 |
| Null tests | `IS NULL`, `IS NOT NULL` | |
| Sets/ranges | `IN (<literals>)`, `BETWEEN` | `IN` over literal lists only (no subquery node exists to accept); **a `NULL` literal inside an `IN` list is a bind defect** [EM-12] — `NOT (x IN ('a', NULL))` is NULL for every non-matching row (verified), the `NOT IN` trap returning in authored form; refused by a gate-1 structural predicate (K4), G-07 reject row; list members and `BETWEEN` bounds family-checked (P-9 rule 1) |
| Pattern | `LIKE` | simple SQL pattern, portable; **the `ESCAPE` clause is rejected** [AE-9] — a structural predicate on the `Like` shape (fail-closed: custom-escape semantics are unpinned by G-08 and translate poorly to Mongo regex; admitting it later is additive growth with its A-15 row + portability note), G-07 row; `RLIKE` **excluded** (Java-regex portability to the event lane is poor — named growth) |
| Conditional | `CASE WHEN … END`, `coalesce`, `nvl`, `nullif` | `nvl` documented as `coalesce/2`; branches/arguments family-checked (P-9 rule 1 — `coalesce(dec_col, 'x')` rejects [AE-1]) |
| Numeric fns | `abs`, `round`, `floor`, `ceil`, `greatest`, `least` | `round` = HALF_UP on decimals — pinned with **genuinely discriminating** rows [EM-8]: `round(2.5)` = 3 and `round(1.245, 2)` = 1.25, with `bround`'s divergent results (2, 1.24) as negative controls (`round(1.245)` = 1 under both modes — not a tie at integer grain — pins nothing) |
| String fns | `length`, `trim`, `ltrim`, `rtrim`, `upper`, `lower`, `substring`, `concat`, `replace` | verbatim, no collation; argument families per signature (P-9 rule 1 — `length(int_col)` rejects [AE-1]) |
| Temporal fns | `year`, `month`, `day`, `datediff`, `date_add`, `date_sub` | timestamp→field extraction depends on the **UTC session pin** (005.1 §6.2) — as do the **implicit timestamp→date casts** inside `datediff`/`date_add`/`date_sub` over timestamp arguments [EM-10]; the session pins touch check semantics in exactly **two** places — here (UTC) and the arithmetic row's null-on-zero (ANSI-off) — and G-08 carries discriminator rows for both, incl. `datediff` over timestamp arguments |

**`CAST` is excluded** (every syntax): candidates are typed, so casts buy nothing a declared schema doesn't already give — and under the pinned ANSI-off session, `cast` silently truncates (`'1.239'` → 1, A-5's verified hazard), the exact two-semantics trap admission paid `try_cast` to kill. Named growth: `try_cast` with a customer.

### 6.3 Aggregate position (`batch_check.aggregate` only)

`sum`, `count`, `min`, `max`, `avg` — over scalar-position expressions of §6.2; no nesting of aggregates; the top-level expression may combine aggregates with §6.2 arithmetic (`sum(net) + sum(fees)`). Empty-set semantics pinned in §7.5.

**The row-count idiom [EM-9]:** `*` is not in the allowed set, so `count(*)` is unauthorable — the authorable row-count form is **`count(1)`**, documented here and in the 009 authoring guidance (§16.1); `count(col)` **skips NULLs** (verified: 1 of 2 rows counted over a column with one NULL), so a reconciliation row-count over a nullable column silently undercounts — trap named, G-08 discriminator row (`count(1)` vs `count(nullable_col)`).

**Exactness under P-9 rule 2 [EM-3]:** an `aggregate`/`control.expr` must *compile* to an integral or decimal type. `avg` and `/` remain authorable over decimal operands (engine-verified: `avg(decimal(38,2))` → `decimal(38,6)`, `sum(decimal)/count(1)` → decimal) and are bind defects over integral operands (`avg(int|long)` → DOUBLE, `sum(int_a)/count(1)` → DOUBLE); an average over an integral column is authored by declaring the column decimal, or reconciled as separate `sum` and `count` checks.

### 6.4 Versioning and CI pinning

The gatekeeper (`core/check_grammar.py::validate_expression(text, position, schema) -> ValidatedExpr | GrammarDefect`) is plain-value pure (sqlglot is a pure-Python dependency, exact-pinned in `pyproject.toml` — a version bump is a reviewed semantics event, same class as a Spark upgrade).

**The executed-text rule [EM-6][AE-2].** `ValidatedExpr` carries **`authored_text`** — the authored string **byte-exact** (the field is named so no builder innocently executes a regeneration) — plus the referenced-column set (K3's input) and P-9's family annotations. The authored text is the **single string** that gate 2 compiles and that stage-time `F.expr` receives; sqlglot is acceptance judge and reference/family **extractor only** — its regenerated SQL is never executed (the renderer rewrites `nvl`→`COALESCE`, `ltrim`→`TRIM(LEADING …)`, `day`→`DAY(TO_DATE(…))` — verified — so executing it would put a second evaluator's renderer into runtime semantics, where a render bug or version bump changes behavior with no CI tripwire: exactly the two-evaluators trap P-2 rejects, on the execute path). One scoped carve-out: the **aggregate position** is framework-compiled from the accepted AST for §7.5's empty-set mechanics [EM-4], with its agreement against `F.expr(authored_text)` G-08-pinned per corpus row **and property-pinned over generated aggregate expressions (§13.2 [DC-2]), the coalesce-cast dtype oracle pinned to the engine with a bind-time equality assertion (§7.5 [DC-2])**. G-07 asserts `ValidatedExpr.authored_text == input` on every accept row, and §13.2 carries the executed-string-equals-authored property.

**The allowed-node set is defined against the pinned parser's actual parse shapes [EM-2]** — generated and verified from the G-07 accept corpus (per-construct expected-node-set assertions), never authored from surface syntax: sqlglot normalizes aggressively (`ltrim`/`rtrim` → `Trim`, `nvl` → `Coalesce`, `year`/`month`/`day`/`datediff` inject `TsOrDsToDate` wrappers, `date_add`/`date_sub` → `TsOrDsAdd` + `Var`, `date_sub` additionally synthesizing `Mul` + `Neg` — all verified), so a hand-enumerated set matching §6.1's prose would fail-closed-reject allowlisted constructs. The gate is therefore node-kind enumeration **plus per-node structural predicates**: the literal-text scientific-notation predicate (§6.1), the [EM-1] `Cast` shape, the [EM-12] `IN`-list `NULL` refusal, the [AE-9] `Like` shape, and function-name resolution for normalized nodes.

CI pinning is three-fold: the **accept/reject corpus** (every §6.1–§6.3 member accepted; every named non-member rejected; **per function, the [DC-3] signature obligation: ≥1 signature-conforming accept row and ≥1 per-argument-position cross-family reject row** — G-07), the **executable semantics table** (every allowlisted construct evaluated on the engine under the session pins, discriminator rows included — G-08, A-15's idiom), and the **cross-lane check-verdict vectors** (§13.3). Per-function **event-lane portability notes** ride the data module as fields (Track A's input), never as behavior.

### 6.5 Bind-time expression typing (P-9)

Two rules, two oracles — one decision answering [AE-1] and [EM-3]; rationale in P-9's Y-statement, defect rows K9/K5 (§5.4), consumed by §7.5's comparison semantics.

- **Rule 1 — family coherence (parse-phase, AST-side) [AE-1].** A bottom-up family computation over the accepted AST: the coarse partition `{string, numeric, temporal, boolean}`; column refs take their declared type's family (the bound schema, K3's ground), literals their literal form's, `NULL` is polymorphic; every §6.2/§6.3 data-module entry carries **argument/result family signatures** beside arity — **the signature set's one normative home is the data module under the G-07 corpus obligation (P-9's [DC-3] Y-note): per function, ≥1 signature-conforming accept row and ≥1 cross-family reject row per argument position; no prose signature table exists, deliberately**. Reject (`check-expression-mixed-types`) any comparison, arithmetic, `IN`, `BETWEEN`, or function-argument site where string meets numeric or temporal, or where an argument violates its signature. Coarse by design: a restriction on authorship, never a prediction of engine semantics — nothing admitted here is evaluated by anything but Spark.
- **Rule 2 — compiled-dtype inspection (bind-phase, engine-side) [EM-3].** Gate 2's compiled plan is the type oracle — no second type calculus exists: row `expr` must compile to BOOLEAN (`check-expression-not-boolean`); `aggregate`/`control.expr` must compile to integral or decimal (`check-expression-inexact-type`), refusing the engine-verified DOUBLE producers (`avg(int|long)`, `/` over integrals) while `avg`/`/` over decimals stay authorable (§6.3). Exactness is enforced where it is load-bearing (§7.5's comparison); row-position DOUBLE intermediates are the named, G-08-pinned residual.

## 7. The `post_check` Interpreter

The stage's shape (framework code, `stages/post_check.py` + `frames/business_checks.py`): compile once per fact type, evaluate per type, shape and append once, then render the batch verdict. Pipelines contribute **zero check code and zero attribution code** — restated as law (D-1, D-6); there is no code path from a pipeline package into this stage.

### 7.1 Compilation

`frames/business_checks.py::compile_business_checks(checks: ChecksModel, fact_type: str, schema: FactSchemaModel) -> CompiledBusinessChecks` — a frozen value per type: an ordered tuple of entries, **entry 0 = the framework-reserved implicit check** (id `missing-domain-id`, reason `business/missing-domain-id`, version `"fw-1"`, predicate `domain_id_col IS NULL` — D-6: evaluated first, before all authored checks; entry 0's id is **framework-reserved** — `RESERVED_CHECK_IDS`, §4.2 [AE-6] — so no authored check can collide with it in `reason_detail`), then the type's authored checks in authored order (P-5). Row-check texts were validated at bind (P-2); compilation renders them via `F.expr` over **`ValidatedExpr.authored_text`, byte-exact** (§6.4's executed-text rule [EM-6][AE-2]) — the linter's string-SQL sink rule gains the named exemption `("spine/frames/business_checks.py", "_compiled_expr")`, the §6.2-`_typed_expr` precedent (005.1 §12.6). `apply` perceived only declared `valid_df` columns (D-4) and the interpreter perceives only declared candidate columns — lineage is not in scope for any expression, by construction.

### 7.2 Evaluation — one evaluation, two outputs, three-valued law

Per fact type: membership joins first (P-8's markers), then one projection builds `_conveyer_business_failures` = `filter(array(<struct(id, reason, version) per entry, evaluation order>), x -> x.failed)` — the 005.1 §6.3 idiom restated for candidates. **The three-valued law (normative):** an authored row `expr` is the condition that must **hold**; a row **fails iff the expression evaluates to FALSE**; TRUE and NULL both pass. NULL-tolerance is deliberate and uniform (membership's P-8 rule is the same law): null-handling is one check's job, and that check is admission's or an authored `IS NOT NULL`. The 009 authoring guidance and the cross-lane vectors (§13.3) both carry NULL cases — the event lane must reproduce this law exactly. The implicit check and membership markers compose into the same array; the internal column is dropped before any frame leaves `frames/` (the `conveyer-azr` privacy rule; the sanctioned seams are the two projections `admitted_candidates(evaluated)` / `business_violations(evaluated)`).

### 7.3 Reason shaping (D-6's grain, mechanical)

Per violating candidate row: `reason_code` = the first entry's `reason` (implicit check first ⇒ a null-`domain_id` row's code is deterministically `business/missing-domain-id`, authored failures riding the detail — D-6 verbatim); `reason_detail` = deterministic `to_json` of the failures array projected to `(id, version)` — statically ordered structs, compile-time-fixed fields, no maps (the A-7 argument holds unchanged); truncation at 32 entries with the terminal `{"truncated": <n_total>}` element (005.1 §6.4's rule, reused). Ids and versions only — never reasons' free text beyond the code, never column values ([S-9] by construction: cell values are unreachable from compile-time struct literals).

### 7.4 Versions (P-3, mechanical)

`checks_version` computed once at binding (`core/contract.py::checks_version(checks) -> str`, the A-11 functions' sibling), accreted seed-adjacent, stamped by the post writer into the `check_version` column; per-check versions computed at compile from each parsed `CheckModel` (`canonical_json(model_dump(mode="json"))` — key-order-insensitive by the canonical grammar, G-suite property). Ledger: no schema change; the version rides quarantine rows and the context, not the ledger.

### 7.5 `batch_check` evaluation and sequencing

Dormant until the member grammar lands (P-6); its semantics are pinned now so 005 v1.x implements against a finished spec:

- **Subject: the candidate set**, pre-subtraction — D-5's wording ("the aggregate expression over the detail member's candidates") is deliberate: reconciliation tests what the delivery *asserted*, and a quarantined line must not silently rebalance the totals it was delivered under. A batch can therefore fail both ways at once (rows quarantined *and* reconciliation broken) — both facts are recorded (§7.6's sequencing).
- **Comparison semantics, pinned:** `tolerance` absent ⇒ the verdict is `aggregate = control` under SQL numeric equality (decimal comparison numeric, scale-insensitive); `tolerance` present ⇒ `abs(aggregate − control) <= tolerance`, all-decimal/integral arithmetic, exact — floating point is excluded **by P-9 rule 2 [EM-3]**, not by the grammar alone: `/` over integral operands and `avg` over int/long columns compile to DOUBLE on the pinned engine (verified — the grammar admits both), so the bind step refuses any `aggregate`/`control.expr` whose compiled type is not integral or decimal (`check-expression-inexact-type`, §6.5); what evaluates here is decimal/integral end to end and the exact-equality verdict is meaningful. A NULL on either side is never a pass — and NULLs are **decomposed by provenance**, never conflated: the aggregate side per the next bullet [EM-5]; a **NULL extracted control value** (the control member's single admitted row, whose contract left the control column nullable, yields NULL) fails as **`control-unavailable`** [AE-4] — data-driven (the control cell is absent or bad; not a mismatch — nothing was compared — and not P-6(b) — nothing was quarantined; remediation is a corrected delivery), demoting to the drift probe when facts are present like every other verdict; the 009 authoring note (§16.1): declare the control column `nullable: false` so the same failure surfaces one stage earlier, at admission, as P-6(b).
- **Aggregate-side NULLs decompose by provenance [EM-5] — the verdict is a function of `(candidate_count, aggregate)`, both already at hand in one aggregation pass:**
  - **Empty candidate set (`count == 0`):** `count` is naturally 0; **`sum` coalesces to typed 0 per aggregate node [EM-4]** — the injection grain is pinned: the wrap is `coalesce(<that sum>, 0 cast to that sum's compiled result type)` around **each individual `sum(…)` call**, never the top-level expression (`coalesce(sum(n) + 5, 0)` = 0 while `coalesce(sum(n), 0) + 5` = 5 over the empty frame — engine-verified divergence; per-node is the D-5 register's own reading: each absent detail totals zero, then the authored arithmetic applies — absent optional detail ⇒ reconcile against the summary total, a nonzero total failing loudly, the summary-claims-what-detail-lacks case caught for free). **Mechanism [EM-4]:** the aggregate position is compiled by the framework from the accepted gate-1 AST as a **Column-expression tree** (`check_grammar.py::compile_aggregate` — the allowed aggregate surface is five functions + §6.2 arithmetic + literals, every node already enumerated), so the per-node wrap is framework composition at compile — never a regenerated-SQL rewrite, keeping §6.4's executed-text rule intact (no sqlglot-rendered text executes). **The cast's dtype oracle, pinned [DC-2]:** "that sum's compiled result type" is the **engine-compiled type** — the dtype the engine assigns the `sum` node in **gate 2's compiled plan of the authored text** (P-9 rule 2's one-oracle rule read at node grain; no second type calculus, no sqlglot-derived type) — and bind additionally **asserts equality** between the structural Column tree's engine-analyzed dtype for that node and the oracle's answer: a hard, fail-loud bind assertion whose violation is a **framework defect** (the `compile_aggregate` translator disagreeing with the engine's typing of the authored text — never an authored-spec `bind-defect/*`), surfacing pre-land with A-10's deterministic retry burn rather than as a stage-time cast surprise. The structural compile's agreement with `F.expr(authored_text)` is G-08-pinned per aggregate corpus row **and property-pinned over generated aggregate expressions (§13.2 [DC-2])**, and gate 2 + P-9 rule 2 still run over the authored text. `min`/`max`/`avg` take no zero: over an empty candidate set they yield NULL and the check **fails loud** (`control-unavailable` class — "the minimum of nothing" reconciling against a control is an authoring error surfaced as data). G-08 carries empty-set rows for combined expressions (`sum(net) + sum(fees)` → 0; `sum(net) + 5` → 5) [EM-4].
  - **Non-empty candidate set, NULL aggregate (`count > 0`) [EM-5]:** a distinct named failure — **`aggregate-unavailable`** — never coalesced to 0 and never given the empty-set framing. Its two known provenances: an **all-NULL aggregated column** (`sum(amt)` over delivered rows whose `amt` is all NULL — silently coalescing would reconcile delivered rows as if none existed) and **decimal `sum` overflow under the ANSI-off pin** (NULL over a non-empty set — coalescing or reporting it as mismatch would mask an overflow defect as a data verdict). Remediation differs from mismatch (inspect the delivered column / the declared precision), which is why the class is named. G-05/G-08 rows: all-NULL-column `sum`; a near-precision-38 overflow `sum`.
- **Verdict channel:** fresh path, facts absent — a failed comparison (or `control-unavailable`/`control-ambiguous`/`aggregate-unavailable` [EM-5]) **fails the batch loudly** after the quarantine append (§7.6): deterministic plain `ValueError`, value-free message (`batch-check-failed: id=<id> verdict=<mismatch|control-unavailable|control-ambiguous|aggregate-unavailable> check_version=<checks_version[:16]>`), burning retries by design; remediation is a corrected delivery (supersession). Facts present (ANY table — §8.4): **demoted to the drift probe**, never raised.

### 7.6 Stage sequencing (normative)

Evaluate all row/membership checks per type → shape and append the union of violations (one guarded append, §8.1) → **then** evaluate `batch_check` and render its verdict. Append-before-verdict is deliberate: the quarantine rows are remediation's evidence for *why* the batch failed, and errors-as-data wants them durable even when the batch dies loudly one step later. The rerun of a batch_check-failed batch re-enters through the doors (quarantine guard present → subtraction; facts absent → the verdict re-renders and fails again, deterministically) — a failed reconciliation stays failed until a corrected delivery supersedes it, and its quarantine rows remain as honest history (a batch with quarantine rows and no facts; complementarity is per-batch trivially intact).

## 8. Subtraction, Doors, Identity — §5.4 at Implementation Grain (P-7)

### 8.1 Fresh path

Per type: §7.2's evaluation; `admitted_facts[t]` = empty-failures projection; violations = the complement. **Count identity per type**, asserted on the genuinely-fresh path only: `|candidate_t| == |admitted_t| + |violations_t|` ([H-2]'s fresh-only rule at the new grain). Shaping (§10) unions all types' violation rows into **one guarded append** keyed `(batch_id, "post_check")` — quarantine is one table with one post-stage writer, so I-4's one-commit invariant is untouched by multi-type pipelines. Zero violations across all types ⇒ no write, no guard row (naturally idempotent; the door below covers its rerun). `violation_subtraction` is **retired** (P-7(c)): the fresh split preserves [DC-5]'s bag semantics — in-memory, multiplicity-preserving, UDF-free on the admit path — because complementary filters over one evaluated frame *are* the bag subtraction when the subtrahend is framework-computed. Registered as a 006 §5.4 wording erratum + the errata-notes item 18 supersession (§16.5): item 18 retained the function *for the interim's opaque pipeline-returned frame*; the interim ends here.

### 8.2 The door planner

`core/doors.py::post_check_path(q_guard_present: bool, fact_presence: Mapping[str, bool]) -> PostCheckPath` — plain-value pure; `PostCheckPath ∈ {FRESH, DURABLE_SUBTRACT, DURABLE_AUTHORITY}`. `fact_presence` = one `table_has_batch` probe per declared fact table (P-1's enumeration — the same mapping 007.1 F-4 iterates); the door fires on `any(...)`. Decision table:

| q_guard | any-table facts | Path | Behavior |
|---|---|---|---|
| absent | absent | FRESH | §8.1 |
| present | — | DURABLE_SUBTRACT | §8.3 |
| absent | present | DURABLE_AUTHORITY | [R2-1]: empty violation set, `admitted_facts[t] = candidate_facts[t]` per type, **no append**, recompute demoted to the drift probe; no count identity |

**Why ANY (normative — the [H-2] wedge argument, per-table grain):** a kill between type appends leaves facts of type A durable and type B absent. The verdicts that admitted A's facts were already rendered by the attempt that committed them; a rerun re-rendering verdicts against re-resolved co-effect snapshots (D-2's rerun bullet) while A stands durable can quarantine candidates whose siblings are already facts, or fail the batch outright — re-adjudication with partial durable state, the exact wedge [H-2]/[R2-1] closed at batch grain. Under errata row 19 the sound composition is: **batch-grain authority** (any durable fact ⇒ the batch's judgment is settled; this doc) over **per-table completion** (B's append still proceeds through its own guard/delta path; 007.1 F-4). An ALL-tables door would re-adjudicate in exactly the partial-kill window; a per-table door would render *fresh* verdicts for B against drifted perception while A's stand — two attempts' judgment inside one batch. 006 D-3's perception-contract clause 2 stays per-table true throughout (`conveyer-3w8` item 4): each table's snapshot never shows a partial batch of *that* table; the doors are about verdict authority, not table visibility. **pre_check's [DC-1] door migrates identically**: 005.1 §6.6's `f_present` probe becomes the ANY-table composition over the same enumeration (proposed 005.1 erratum, §16.3).

### 8.3 Guard-present rerun — hash-keyed subtraction, per type

Per type: recompute candidates; shape each candidate's snapshot **with the `_conveyer_fact_type` tag** (P-7(b)) through the §10 UDF (the one admit-path UDF cost, rerun-only — A-7's claim intact); anti-join the durable `row_hash` set for `(batch_id, "post_check")`; `admitted_facts[t]` = survivors. Sound by construction twice over: value-determinism (D-1 — verdicts are functions of row value + pinned snapshots, so recomputed violating rows hash identically to their durable quarantine rows) and now **type-discrimination** (the tag makes a type-A quarantine hash inert against a value-identical type-B candidate — the silent-drop construction of P-7 is unrepresentable). **Drift probe:** recompute violations per type, hash, compare the union against the durable set — `post_check_drift` = `None` on equality, else the value-free summary `"post_check drift: durable=<d> recomputed=<r> only_durable=<a> only_recomputed=<b> checks_version=<hash[:16]>"` — recorded via the existing channel (ledger `error_message` on non-failed rows, WARNING, EMF `PostCheckDrift`), never raised. No count identity on this path ([H-2]). The anti-join consumes only rows the original attempt adjudicated — a **drift-born** candidate (new under re-resolved co-effects, no durable hash to subtract against) survives into `admitted_facts[t]` by construction; if it carries a NULL `domain_id`, the I-24 backstop at commit is its named ground, not this stage's — §11's [AE-3] row and 007.1 §7.3's path-2 qualifier.

### 8.4 The `batch_check` demotion door

Independent of the row-path doors: `batch_check` renders a verdict **iff no declared fact table has the batch** (the ANY composition again); otherwise every batch_check outcome — mismatch, `control-unavailable`, `control-ambiguous` — demotes to the drift probe: the recomputed aggregate-vs-control comparison is recorded as data (§12's value-free form), never raised. 006 §5.4's door extension made mechanical: durable facts are authoritative through every door, row or batch.

### 8.5 The tripwire, restated at the seam it guards

006 §5.4's law is this section's standing guard: every kind evaluable here is value-determined, which is what makes §8.3 sound. A proposed kind whose verdict is occurrence- or dataset-relative must be rejected or must carry its own identity mechanism *as part of its design* — this section is where that review happens (§15).
